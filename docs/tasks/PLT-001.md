# PLT-001 线程被锁死：止血 + 救活（`Duplicate namespace`）

- 派单人：`codex-总监`（依据 `修复Bug` 线的只读调查 + 我的独立复核）　执行：老板授权后，由当值线做
- **类型**：`incident`（**故障**：一条在岗的线已彻底不能工作）　**严重度**：`S2`（主要功能受损；单线死亡，且牵涉明早执行链）
- **优先级**：`P1`　**卡住了谁**：`codex-量化总监`（第一号对话框）的全部工作
- 范围：`C:\Users\Administrator\.codex\config.toml`、`thread_history_1.sqlite`；**均在工作区之外——每次写操作都必须老板授权**

## 一、故障现象

`codex-量化总监`（线程 `01a0877b`）**每一轮都被平台 400 拒收**，报错：

```
Duplicate namespace name 'mcp__deepseek_harness' in input[1396].tools[0]
```

含义：请求里工具清单的 `mcp__deepseek_harness` 命名空间出现两次，违反唯一性 → **整条请求被拒，那一轮根本没启动**。不是模型答错，也不是"忙"。

## 二、证据链（rollout 级，可复核）

- 全盘扫 `.codex\sessions\*\*\*\*.jsonl`：**真正带此错的只有 `01a0877b`**（L4764、L4770 连续两轮）；其余命中均为转贴文本。
- 该文件里 `mcp__deepseek_harness` 共出现 4 次 → 与"两次 `tool_search_output` 各带一份命名空间"吻合。
- **因果时间线（本地时间）**：

| 时间 | 事件 |
| --- | --- |
| 09-10 03:16–03:41 | `01a0877b` 装桥（`npm install` → WSL `/home/lgy/.dsh-bridge`，生成 `run-mcp.sh`） |
| 09-10 03:42:07 | 备份 `config.toml → config.toml.bridge-backup`（**先备份，这点做对了**） |
| 09-10 03:42:40 | `apply_patch` 追加 `[mcp_servers.deepseek_harness]`（5 行） |
| 09-10 03:42:48 | `codex mcp list` 验证注册生效 |
| 09-11 04:17:57 | 桌面端为 `D:\agent_crew_kits` 写 `trust_level` 时**整份重写** config.toml，该段被原样带过去 |
| 09-11 05:58:54 | 第一次 `tool_search` 到该命名空间 → **没事** |
| 09-11 05:59:15 | 第二次 `tool_search` 到**同一命名空间** → 历史里两份 → **此后每一轮 400，线被永久锁死** |

**根因**：平台把 `tool_search` 的发现结果当历史项回放，而该项自带 `tools`（命名空间定义）；同一条线重复发现同一个 **deferred** 命名空间两次 → 历史里两份同名 → 违反唯一性。

## 三、处置顺序（**不可颠倒**）

1. **① 止血（先做，最急）**——否则救活后它再搜一次又被锁死，而且**其他长线（含 `codex-总监`）同样暴露**。
   - **【2026-09-11 06:4x 更正：止血 ≠ 根除】** 已执行（把 `[mcp_servers.deepseek_harness]` 注释掉，见 `scripts/plt001_stop_bleed.py`），但独立核验证明**风险类别仍在**：`defer_loading` 是**客户端通用行为**（第一次 tool_search 里 `mcp__node_repl`——Codex 内置、人人都有——同样带 defer）。所以本步的准确表述是「**降低触发面**」，不是「风险已消除」。
   - **后续两条**：(i) 探明客户端有没有**全局关闭 deferred / 把内置 server 也排除**的开关（只读探，有证据再动）；(ii) 执行纪律：**不许对同一 deferred 命名空间连搜两次**（已写进 `AGENTS.md` 红线 + `docs/LESSONS.md` L12）。
   - 首选：给该 MCP 关掉 deferred 通道（先例：`plugins/cache/openai-bundled/unified-computer-use/.mcp.json` 里的 `omit_tools_from`），工具不进 deferred，`tool_search` 就搜不到它；
   - 备选：**改名或摘掉** `[mcp_servers.deepseek_harness]`（桥不是刚需，现有看板 + 信箱已能替代大部分用途）。
2. **② 救活 `01a0877b`** —— **【2026-09-11 06:3x 更正：修库这条路已实测无效】**
   - **实测证据**（只读勘察，`scripts/plt001_inspect_history.py`）：
     - `thread_items` 里该线 1424 行，类型只有 `reasoning / commandExecution / agentMessage / userMessage / fileChange / webSearch / mcpToolCall / contextCompaction` —— **根本没有 `tool_search_output` 这种类型**；
     - 含 `tool_search` 的 49 行**全是 `reasoning` 文本**（模型在想"要不要搜"），不是带命名空间定义的输出项；
     - 含字面量 `mcp__deepseek_harness`：**0 行**。
   - **结论**：那条脏项**不在 SQLite 投影里，只在 `rollout-*.jsonl` 原始账本里**（请求是按 rollout 回放构造的）。
   - **因此**：
     - **首选改为「新开线程承接 `codex-量化总监` 这个名字」**（写锚点交接，旧线只读退役）——**零损坏**，代价是丢它的历史连续性；
     - 若坚持要"保这条线"，只能动 rollout，而 §6.5 已写明**投影存着字节偏移，不能删行**——要做就得设计"**等字节长度替换**"（把那一行的 `tools` 清空但保持总字节不变），**风险高，需另行设计 + 全量备份**，不作为首选；
     - **不许**为了省事直接删行。
3. **③ 上游**：请求构造时对命名空间去重 —— 平台侧，本地改不到，登记为待办，不许拿本地改造冒充。
   - **附**：桥侧无 `defer` 代码、安装者照 README 且先审源码/先备份/后验证 → **不追责**；本卡只记"平台缺陷 + 流程改进（改全局配置要登记影响面）"。

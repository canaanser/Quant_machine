## 一、最新实验结论（已完成，可复现）

1. **版本**：`@deepseek-ai/dsh@0.1.5-rc.1`。web profile 的 `cordis.patch.yml` 已启用 schedule overlay（用 `tools/mobile_chat/schedule_overlay.mjs apply` 写入；`revert` 可撤）；`--dump-config` 可预检（`node <npx>/dsh --profile web --dump-config | grep schedule`）。
2. **时间唤醒已验证**：主 GUI 会话（workspace `/home/lgy/lab/股票`，session `session-b68ddbdb-9523-4eda-b675-02c69eb55bda`）在 17:26 建了 `schedule-1`（5 分钟后）与 6 条守盘提醒；`schedule-1` 于 17:31:18 **准点触发**，会话自动起回合并回复确认。
3. **机制要点**：提醒以“同会话 follow-up 消息”投递；**需要活着的 root agent**；会话关闭时提醒保持逾期直到恢复；固定间隔最小 5 分钟；无 push/短信/邮件。
4. **热窗口观察**：工作结束后会话会保持“热”一段时间；热窗口内提醒即时投递。**“5 分钟固定提醒把热窗口接起来”的保持清醒链条尚未实测**（老板关心成本，约 72 回合/交易时段，需先给成本评估）。
5. **Web RPC（已打通，2026-09-10 21:43 看板侧实测）**：正确端点是 `POST /api/session/<method>`（不是 `/api/remote.mux`）；`session/prompt`（sessionId/requestId/mode/content）对**冷会话**可直接唤醒（accepted + 0.9s 回复）。凭证链路：`GET /?token=<launchToken>`（Host 绑定换 cookie）→ cookie 由 `~/.dsh/.credentials.yaml` 持久保存，跨重启有效；`launchToken` 从 `/home/lgy/.dsh-web.log` 抓取，**不需要老板手抄**。注意 `requestId` 去重有竞态，重试间隔建议 ≥2s。

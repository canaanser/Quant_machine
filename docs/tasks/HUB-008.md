# HUB-008 工程管理化：任务/项目 接口扩展

- 派单人：老板　落单：`codex-看板编辑`　接手：`codex-看板编辑`
- **类型**：`dev`　**优先级**：`P1`　**卡住了谁**：要从"聊天工具"变成"工程项目管理通讯软件"
- 范围：`tools/mobile_chat/*` 与文档（只读别人的工位；不写别的仓）

## 一、目标

把散落的三处"任务"合成**一张可查询的任务表**，并给出**建卡/流转**的接口——
这是"工程管理"与"聊天"的分水岭：**聊天是消息，工程是单据**。

现状（散落的真源）：

| 来源 | 位置 | 缺什么 |
| --- | --- | --- |
| 任务卡 | `docs/tasks/<ID>.md` | 没有统一的机器可读视图（要 grep 文件） |
| 派单 | `outputs/inbox/*.task.json`（含 `done/`） | 与卡不对应（有的派单没有卡） |
| 看板 @ 转投 | 同上（`board_*.task.json`） | 同上 |

## 二、接口（本轮交付）

| 接口 | 作用 |
| --- | --- |
| `GET /api/tasks` | **一张任务表**：合并"卡 + inbox 派单"，每条给 `id/title/kind/assignee/state/project/source/file/updatedAt`；再按**前缀**分组当"项目/组件"（HUB/KIT/TRD/NET/DAT…） |
| `POST /api/tasks` | **建卡**（HUB-004 的后端）：自动取号（`TASK_ID_STANDARD` 规则：取最大+1，不跳号不复用）→ 按标准模板落 `docs/tasks/<ID>.md` → 投对方信箱 → 看板留一条系统记录 |
| `POST /api/tasks/status` | **状态流转**：`open/claimed/blocked/done/dropped`，写**侧车**（不改卡）：`outputs/dialog/tasks_state.json`，留 `by/at/note` |
| `GET /api/events` | **SSE 实时通道**（见 HUB-007）：任务/消息/暂停状态一变，页面秒级刷新 |

## 三、护栏（承自各卡）

1. **必填校验**：建卡必须有 `title + assignee + acceptance`（**没有验收标准不许派**——HUB-004 定）；
2. **取号纪律**：前缀必须来自 `docs/TASK_ID_STANDARD.md` 的表；`max+1`；**已开工的单永不改号**；
3. **不写别人的仓**：建卡只写本仓 `docs/tasks/`；投递走信箱/queue；
4. **状态是投影**：卡文件是"规范真源"，`tasks_state.json` 是运行态；两者冲突时**以卡为准**并在接口里标注 `conflict:true`；
5. 幂等：同一 `id` 重复建卡 → 409，不覆盖。

## 四、验收

1. `GET /api/tasks` 能把现有卡 + 派单合成一张表，并给出分组计数；
2. `POST /api/tasks` 建出来的卡能被 `GET /api/tasks` 立刻看到，且号连续不撞；
3. 缺验收标准 → 400；重复 id → 409；未注册 assignee → 400；
4. `POST /api/tasks/status` 改状态后，`GET /api/tasks` 反映出来且带 `by/at`；
5. `selftest` 补用例并全绿。

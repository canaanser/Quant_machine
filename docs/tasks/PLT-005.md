## 二、设计（一句话：所有"会改变世界"的动作，统一过一道 guard）

```
动作发生前 → guard(action, actor_slug, target) → 读员工卡(level+permissions) + 常设授权表
                                              → allow / deny(说明+替代路径) / needs-boss(排队等拍板)
                                              → 结果一律 append 到 outputs/dialog/audit.ndjson
```

**原则四条**
1. **单一真源**：能不能做，只由**员工卡**（`level` + `permissions`）与**常设授权表**决定；散在各处的 if 一律收回。
2. **唯一入口**：动作不许绕开 guard 直连（Hub 口、宿主口、git 口都要过）。
3. **拒绝要教路**：deny 必须给"改走哪条路"（例：`组员不进看板发言；请改投组长信箱 say.mjs --mail --wake`）。
4. **fail-open 要标出来**：拿不到 level/permissions 时**默认放行**，但**写一条 warn 进审计**（宁放勿堵，与老板面开关一致）。

**动作清单（分期）**

| 期 | 动作 | 判据 | 现状 |
| --- | --- | --- | --- |
| **P0** | `board.post` | `level ∈ {boss, director, lead}` | **已在 HUB-018 排（H）**：member→400 |
| **P0** | `merge.main` | 卡上 `permissions` 含 `merge-main` | 目前靠"总监审阅"的自觉；guard 化后可机判 |
| **P1** | `service.restart` / `schedule.task.*` | 必须有**老板发的常设授权**（登记在授权表） | 今晚"看板编辑可自行重启"就是这种授权，但只写在文档里 |
| **P1** | `thread.spawn` / `thread.message` | 卡上 `spawn-subagents`；且**禁止**用 app 委派工具给别的线派活（会写坏对方） | 已两次实证事故（`docs/LESSONS.md` L12 族） |
| **P2** | `orders.place` / `secrets.read` | 卡上 `place-orders` / `read-secrets`；**永远 needs-boss** | 现在只有红线，无机制 |

**常设授权表**（guard 的输入之一）：`outputs/dialog/grants.ndjson`，一行一条——
`{ts, by:"老板", to:slug, action, scope, reason, revokeAt?}`；老板给了才写，撤回就置 `revoked`。

## 三、验收（可证伪，缺一不可）

1. `board.post`：member→**400 + 教路话术**；lead→200；**level 缺失→200 且审计有 warn**；系统事实行→200；
2. `merge.main`：卡上无 `merge-main` 的线发起合入→**deny**，并写出它该找谁；
3. `service.restart`：无授权→**needs-boss**（不是 deny：排队等拍板）；有授权→放行，且**每次留痕**；
4. **审计可复核**：`audit.ndjson` 每条含 `ts/action/actor/decision/reason/policy_source`，可逐条追；
5. **不破坏现状**：上线后跑一遍全量自测（Hub `selftest_v2` + 套房 `npm test`），**零回归**才算过。

## 四、红线与边界

- **不碰平台设置**：改计划任务/服务注册仍走"登记 + 回滚点 + 风险说明"三件（`AGENTS.md` 红线）。
- **guard 不能变成新单点**：任一动作的 guard 读不到卡就 fail-open（放行 + warn），**绝不因为 guard 挂了而停摆**。
- **历史不追溯**：guard 只对**上线之后**的动作生效；历史板行/提交不回写。
- **回滚**：guard 以**开关**形式接入（`GUARD_ENABLED`），关掉即退回现状。

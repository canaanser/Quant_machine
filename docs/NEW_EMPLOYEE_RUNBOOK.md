# 新员工创建流程（Runbook）· v1 · 2026-09-11

> 目标：**加一个 agent 不出错**。每一步都写清「怎么做 / 怎么验收 / 禁止什么」。
> 适用：Codex 侧线（DSH 侧同理，把"项目/工作区"换成它的 profile 与会话）。
> 本文件是**操作流程**，与套件仓的 `org/EMPLOYEE_INIT.md`（初始化卡）配套；将来由套件线搬进 `agent_crew_kits/docs/onboarding.md`。

---

## 阶段 0 · 准备（**开窗之前**全部做完）

| # | 动作 | 怎么验收 |
| --- | --- | --- |
| 0.1 | 工位目录存在且**可写** | 写入/删除一个探针文件 |
| 0.2 | 员工卡已入库（`agents/<slug>.card.json`） | 文件在、JSON 合法 |
| 0.3 | 席位**预登记**进 `agents.json`：`label/title/slug/level/workspace` | `slug` **必须与员工卡逐字一致**，且**以显式指定为准**（绝不交给哈希去算） |
| 0.4 | 建它的信箱 `pending_<slug>.ndjson`，放入入职说明 | 文件在、NDJSON 合法（`ConvertFrom-Json` 能过） |
| 0.5 | 任务卡在位（`docs/tasks/<ID>.md`） | 卡里有：类型 / 严重度或优先级 / 验收标准 / 交付物 |
| 0.6 | **把工位目录添加为「项目」**（不是给别的线程加工作区） | 新建对话时，项目列表里能选到它 |

**验收口径**：此时 `GET /api/deliver?alias=<看板名>` 应返回
`unknown / 该席位尚未上岗（没有绑定会话）`——**这是正确的"未上岗"状态**，不是错误。

## 阶段 1 · 开窗（**只能老板在 UI 手动做**）

1. **禁止用工具建线程**：`create_thread` 会给新线程写一条缺 `call_id` 的条目，让它**一出生就 `systemError`**（2026-09-11 04:0x 已再验证，记录见 `docs/BOARD_NAMES.md` §6.5）。
2. UI 新建任务：**项目 = 该工位所在项目**；环境 = **local，不要 worktree**（工位就是那个目录，不能另起副本）；**标题 = 看板名**（如 `codex-套件`）。
3. 第一句话 = 初始化提示词（`agent_crew_kits/docs/FIRST_PROMPT.md` 第一节）。
4. **不许把同一段提示词同时贴给两条线**——两条线改同一文件同一片区域必冲突。

## 阶段 2 · 绑定 threadId（**最常被漏、漏了就叫不醒**）

1. 取**真实** threadId：用 `list_threads` 按**标题 + cwd** 找那条新线——**绝不许抄别人的号**；
2. 写进 `agents.json`：`threadId` + `status: "active"` + 更新 `note`（谁在什么时候绑的）；
3. **验收**：`GET /api/deliver?alias=<看板名>` 的 reason **不再**是"该席位尚未上岗"。

> 没绑 threadId 的后果：席位永远 `unknown` → **永远叫不醒** → 每次都得人工转达。

## 阶段 3 · 上岗自检（**新线自己做**）

1. 读三份（**只读三份**）：`org/EMPLOYEE_INIT.md`、本期任务卡、`docs/redlines.md`；
2. 跑「唤醒自检」六步，逐条贴结果；
3. 一页汇报：现状 / 下一步 / 卡点；
4. 回报「红线已读」，并建起私人文件夹 `.private/<slug>/`。

## 阶段 4 · 首轮验收（**主线做**）

1. **核证据**（别看声明看文件）：私人文件夹四件齐全、`git status` 干净、`spec/` 零改动、未提交；
2. **三条判定**：① 有没有先查信箱；② 有没有认出自己的层级与红线；③ 有没有先汇报再动手；
3. 通过 → 放行第一张任务卡，并**设停点**（拆成 M0-1/2/3，每停一报）。

## 禁止清单（全是今天踩过或差点踩的）

| 禁止 | 原因 |
| --- | --- |
| ❌ 用工具建线程 | 新线程一出生就 `systemError`（`missing field call_id`） |
| ❌ 用 worktree 建工位 | 工位会分叉成两份，产物对不上 |
| ❌ 让哈希算中文名的 slug | 与员工卡对不上，信箱文件名跟着错（`codex-kit` vs `codex-9bb7a0`） |
| ❌ 跳过阶段 2 | 没绑 threadId = 永远叫不醒 |
| ❌ 从沙箱 shell 起常驻进程 | 9/10 事故根因 |
| ❌ 两条线同时改同一文件 | 必冲突 |
| ❌ 物理删文件 | 废弃只标记（历史是资产） |

# 工具收编：把自己造的工具搬进套件（一页）

> 老板 2026-09-13 公告的方式：**各线自己动手搬自己的工具**，本文是唯一口径。
> 目标：把实战里长出来、**跟具体项目无关**的通用工具，从各自工位搬进套件的**新家**——`D:\agent_crew_kits\<模块>\`。

## 一、新家目录（**一个词、小写、自解释**，不要再造新名字）

| 目录 | 收什么 |
| --- | --- |
| `core/` | 真源 / 注册表 / 路由 / 信盒（内核） |
| `cli/` | 命令面（`ack`） |
| `hub/` | 看板 + 信箱 + 名册**服务**（含页面） |
| `host/` | **壳外小工宿主**（镜像 / 门铃 / 自动合入 / 自我重载） |
| `review/` | **门禁 + 合入**（审阅→合 main） |
| `succession/` | **承接换人**（岗位不变、工号换代） |
| `say/` | **安全发送**（正文从文件读 + 回读逐字节校验） |
| `adapters/` | 平台适配器（inbound / outbound / schedule / guard / dsh） |
| `agents/` | 员工卡 |
| `org/` | 组织规约模板（AGENTS 通用版 / 层级 / 交接 / 教训） |
| `spec/` | 契约（信封 / 卡 / 任务 / 回执） |
| `templates/` | 初始化模板（私人夹 / 任务卡） |
| `runbooks/` | 运行手册（闭环 / 承接 / 发送 / 小工） |
| `cost/`、`housekeeping/` | 可选（成本可见 / 清理卫生） |

## 二、每个模块必须"三件套"（缺一件不算搬完）

1. **`README.md`（一页）**：这是什么 / 装它有什么好处 / **一条命令怎么用** / 依赖什么 / **关掉会怎样**。
2. **`module.json`（开关）**：
   ```json
   {"id":"say","name":"安全发送","what":"发板/投信不被静默吞字符",
    "requires":["hub"],"slots":["cli-say"],"defaultEnabled":true,
    "probe":"node say/selftest_say.mjs --probe","health":"node say/selftest_say.mjs --health"}
   ```
   **开关语义**：`enabled:false` = 不载入、不改任何别的模块；`ack enable/disable <模块>` 切换（开=把 `slots` 挂到相关员工卡，关=摘掉）。
3. **自测**：`selftest_*.mjs` 或 `node --test`；**probe 不过不许装**。

## 三、命名规则（简洁、可读，别再堆形容词）

- 目录名：**一个词、全小写**（`say` 不叫 `send-not-eaten`）；脚本名：动词或名词（`say.mjs`、`review.mjs`、`serve.mjs`）。
- **不许**带项目前缀（`quant_`、`stock_`）、**不许**带日期、**不许** `v2/final/new/latest`。
- 旧名要保留时：在 `README.md` 里写一句"旧名 → 新名"，**文件名本身用新名**。

## 四、搬法（**每线自己搬自己的**）

1. **先登记**：在板上回一行「我搬 `<工具>` → 套件 `<模块>/`」，附文件清单。
2. **用 copy，不用 move**：先复制进套件 → 在套件里跑通自测。
3. **项目里留薄壳，不许直接删**：原路径改成一行说明（"已收编到套件 `<模块>/`，见 <路径>"），文件"废弃只标记"。
4. **交活**照闭环契约：`【已提交·待验收】卡号 · 分支 · 短hash ｜ 证据 ｜ 自测 ｜ 未结`；我门禁后合入套件 `main`。

## 五、红线

- **只搬自己造的**（不许搬别人的工具、不许替别人搬）；
- **只搬不改**：搬迁时**不改行为**，要改另开卡；
- **项目专属的不许进套件**（引擎 / 托盘 / 数据链路 / 下单 / 策略 / 回测 / 项目红线），那些留在 `docs/PROJECT_RULES.md` 指的项目里；
- 凭据（token / cookie / 密钥）**绝不进套件仓**。

## 六、分层纪律：**什么固化、什么适配**（2026-09-13 采纳 `codex-修复` 的判断）

> 老板定性"解耦不够、独立性不强"；精确化：**不是耦合不够，是解耦不够——耦合点是有的，只是没收敛到一处**。
> 并且：**不是所有耦合都该消灭**。小工本来就该贴着操作系统活（起进程、写文件、按点触发），那是**必要耦合**；
> 问题是它和**多余耦合**（把平台私有面当 API、把本机路径/编码写死在逻辑里）混在一起。

**判据一句话**：**换 OS、换 agent、换项目之后，如果一个小工需要改代码而不只是改配置，那它现在放错层了。**

| 层 | 归哪 | 内容 |
| --- | --- | --- |
| **固化（契约层）** | 套件 `spec/`+`core/` | 信箱格式与消费语义 · 看板行与署名 · 卡与签字区 · 回执判定 · 身份三件（岗位名 / slug / threadId）· 状态机 · 暂停闸 |
| **适配（宿主层）** | 套件 `adapters/` | 触发与投递（Codex=`queue`、DSH=Web RPC、第三方可能只有"人来看"）· 锁与就绪探测 · 路径与编码 · 常驻方式（计划任务 / systemd / launchd） |

**优先收编的三件（按风险从高到低，来自 `codex-修复` 的实测）**：

1. **平台私有面收成"可探测驱动"**：`codex queue` / `resume` / `thread-writer-locks` / `app-server` **都不是公开契约**——
   实证：应用更新一次，硬编码的 CLI 路径当场失效。每一处都要"**能力探测 + 降级**"（探不到就退回"只落信箱、等本人上线自取"），**不许当硬依赖**。
2. **宿主硬编码收成配置层**：实测散着 `100.64.75.72` 12 处、`E:\stockgate` 3 处、`C:\Users\Administrator` 2 处、`E:\python`/`pythonw.exe`/`wsl.exe`/盘符若干——集中到一处配置。
3. **投递加"发件箱 + 幂等令牌"**：单 `state.json` 多处读-改-写（最后写入者赢）；投递没有幂等 → 进程死在中间就丢一条或发两条。现在那堆"冷却/去重哈希/每小时上限"都是**补丁在挡这一类问题**。

**Windows 的判断**（老板问过）：**可以先做，但不能只有 Windows，且必须写明"哪里没验证"**。今晚踩的坑几乎全是 Windows 特产
（沙箱 ACL 写不了 `~/.codex`、`app-server` 只支持 Unix、`\\.\pipe\codex-ipc` 私有握手、`python.exe` 每 5 分钟闪黑框、8.3 短名打崩 `fs.watch`、`wsl.exe` 与 `\\wsl.localhost`）。
**要紧的一句：在 Windows 上跑通 ≠ 搬到 Linux 能跑——通常要重写那一层，不是重编译。**

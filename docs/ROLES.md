# 角色与上下文分层 v1（2026-09-10）

原则：**主线程不吸收细节；工作线程不继承历史；记忆落文件。**

## 层级

- **L0 老板**：决策与拍板。
- **L1 主线程**（架构 / 审阅 / 调度 / 验收）
  - 输入：老板指令 + `docs/MAIN_ANCHOR.md` + 各线程的“一页报告”。
  - 输出：任务卡（`docs/tasks/<id>.md`）、验收结论、锚点更新、**合入 `main`**（审阅通过后，老板 2026-09-10 授权）。
  - 禁止：读工作线程的完整会话；整读大文件。
- **L2 专职线程**（一个任务一个新线程，用完归档）
  - 审阅线程：输入=审阅单+目标文件/差异；输出=`docs/reports/<id>_review.md`。
  - 工具/插件开发线程：输入=锚点+范围；输出=代码+`docs/reports/<id>_dev.md`。
  - 架构线程：输入=问题陈述+相关文档清单；输出=`docs/reports/<id>_arch.md`。
  - 值守/交易线程：输入=STATE_ANCHOR+计划；输出=日报/回执。
- **L3 执行层**：dsh headless / 值守引擎 / Windows 计划任务。

## 硬规则

1. 主线程只读“一页报告”（模板见 `docs/TASK_TEMPLATE.md`），不读工作线程会话。
2. 工作线程开场只拿：角色卡 + 任务卡 + 指定文档清单（≤3 份）；禁止继承长历史。
3. 一切交付落文件；对话只是传输层。
4. 主线程上下文到 ~50% 就写锚点并换新主线程（`docs/MAIN_ANCHOR.md`）。
5. 跨线程沟通走看板 / `outputs/inbox`（平台“委派消息”有 DeepSeek 兼容 bug，不可靠）。
6. **产品由角色拥有，不绑定线程**：一个产品（如会话工具 Hub）按阶段/任务开新线程，交接靠锚点+进度文档+验收报告；**任何线程都不得成为产品的长期母集**。主线程只做三件事：发任务卡、读一页报告、更新台账与锚点。
7. **通道分工**：看板 = 老板↔agent 人机对话 + 跨系统传话（dsh）+ 告警广播；`outputs/inbox` = 给 dsh 派活；**Codex ↔ Codex 内部协作用文件**（`docs/tasks/<ID>.md` 任务卡 → `docs/reports/<ID>.md` 一页报告 → `docs/WORKBOARD.md` 台账），**禁止用看板当内部总线**；跨线程只读用 `read_thread`，不依赖发消息（平台委派消息有 DeepSeek 兼容 bug）。

# HUB-003 向上敲门铃：把三类事件推给老板

- 派单人：老板　落单：`codex-总监`　接手：`codex-看板编辑`
- **类型**：`dev`（开发）　**严重度**：—　**优先级**：`P1`（阻塞度：链条顶端那一环是空的）　**卡住了谁**：全链条的"往上汇报"
- 范围：`tools/mobile_chat/*` 与文档；走**特批通道**（见 `docs/FASTLANE_20260911.md`）

## 一、要解决的问题

链条是「员工 → 组长 → 总监 → 老板」，但**最上面那一环是空的**：下级交付了、我验收完了，**没人提醒老板**。老板现在只能主动来问。

## 〇、老板端点规格（**老板是真人，不是一条线**；但为合规他仍需要一份"马甲"）

> 老板 2026-09-11 05:5x 定调：**"为了符合规则，我肯定是要有一个马甲，只不过有些许的不同罢了。"**
> 区别就在这里——**agent 的马甲是"替身"，老板的马甲只是"通道与身份"**：

| | agent 的马甲（值守分线） | **老板的马甲（人类端点）** |
| --- | --- | --- |
| 是什么 | 代理回答的影子 | **只提供"通道 + 身份"** |
| 能替他说话吗 | 能（只读代答，必须显式标注） | **绝对不能**——没人能替老板拍板 |
| 门铃 | 信箱 / 会话注入 | **手机通知**（本卡要做的就是这个） |
| 署名 | 代答时标注"本尊不在" | **永远是他本人**，任何程序不得借用 |

**五条硬要求**（本卡与 `HUB-004` 共同遵守）：

1. **可达**：`老板` 是合法收件人（看板行 `- @老板 …` 已在用）；但**还缺他自己的收件箱**（建议 `outputs/dialog/pending_boss.ndjson`，目前不存在）。
2. **可叫**：手机通知——本卡的交付核心。
3. **不可冒充**：token 只证明"有权用这个入口"，**不决定署名**——谁发的就署谁的名。**当前缺口**：手机 token 发出的内容会被记成「老板」，昨晚已实际发生（`codex-总监` 一条留言落款成了「老板」）。
4. **不可被代答**：老板**永远不开值守分线**（`duty` 对他无效）——否则会出现"某条线替老板拍板"，这是灾难级错误。
5. **不进自动登记**：自动登记必须继续**跳过 `老板`**（现在已跳过，保持；不要为了"五处同名"把他塞进 agent 名册）。

## 二、只推三类事件（其余一律不打扰）

| 事件 | 触发 | 必须说清"要你做什么" |
| --- | --- | --- |
| **待验收** | 下级交付一个节点（含任务号 + 一页报告路径） | 「`KIT-001` M0 已交付，待你验收」或「已由我验收通过，需要你知情」 |
| **需拍板** | P0、契约变更、需要授权的提交、涉及钱 | 「需要你授权提交」/「契约要改，需要你点头」 |
| **故障** | `S1`/`S2`（或涉及资金） | 「引擎掉线，已处置/未处置，需要你决定 X」 |

## 二之一、硬要求：**"叫得醒"，不是"画得出来"**（`codex-总监` 2026-09-11 05:4x 追加）

> 只在页面上画一条提示 = **等于没有**——老板不看页面的时候它就消失了。

1. **第一版必须落到手机系统通知 / 浏览器通知**（不是只在页面里弹个 Toast 就算完）；
2. 每条通知**必须带"要你做什么"**；
3. 同时看板要有**置顶一行「待老板：…」**（页面一打开就能看见，补通知之外的兜底）；
4. **平台前提要先探清**（同 HUB-005 的教训：别在没验证的通道上盖楼）：
   Service Worker / 系统通知都要求 **secure context**——手机访问的是
   `http://100.64.75.72:8788`（Tailscale 明文 IP），**大概率拿不到权限**。
   所以第一件事是**实测三问**并落痕：
   ① `isSecureContext` 是什么？② `Notification.requestPermission()` 能不能成？③ `serviceWorker.register()` 能不能成？
   拿不到时的候选：`tailscale serve`（给 `*.ts.net` 上 HTTPS）、或换 Android/微信类已授权通道。
   **探针结果写进本卡**，再定第一版走哪条。

### 二之二、探针结果（**已实测**，2026-09-11 05:5x）

探针脚本：`tools/mobile_chat/notify_probe.py`（只读，无头 Chromium 打真页面）。结果：

```json
{ "origin": "http://100.64.75.72:8788", "isSecureContext": false,
  "serviceWorkerApi": false, "swRegister": null,
  "notificationApi": true, "notificationPermission": "denied",
  "requestPermission": "default" }
```

**结论（决定性）**：明文 Tailscale IP 上 **`isSecureContext=false` → Service Worker 整个不存在 →
Web Push / 系统通知拿不到权限**（`Notification` 对象在，但权限直接是 `denied`，请求也不给）。
**所以"手机系统通知"这一条，在现在的 HTTP 通道上物理上做不到。**

### 二之三、通道候选（按优先级，**都要动平台设置 → 需老板点头**）

| 候选 | 做法 | 备注 |
| --- | --- | --- |
| **A. `tailscale serve`（推荐）** | `tailscale serve --bg 8788` → 手机上改走 `https://<机器>.<tailnet>.ts.net/`，拿到安全上下文，SW + Web Push 可用 | 已探明：Tailscale CLI 在位（**v1.102.3**，TUN 已起），`serve status` = `No serve config`（未配置、可直接上）。**属于平台设置改动，我不擅动** |
| B. 反向代理上 TLS | 本机挂一个带证书的反代 | 要证书；比 A 麻烦 |
| C. PWA/系统级通道 | 装 App 或走已授权通道（微信/钉钉类） | 重、且引入新依赖 |

### 二之四、**最终口径（老板 2026-09-11 05:5x 拍板，"叫不到就叫不到呗"）**

**不上 HTTPS、不折腾通道。** 门铃降级为四件（`codex-总监` 06:0x 转达）：

| # | 门铃 | 形态 |
| --- | --- | --- |
| ① | **凡"待老板"的事一律上板并 @老板** | 不许只压在某条线的信箱里 |
| ② | **手机页置顶一行「待老板：N 条」** | 打开页面一眼看见"要他做什么" |
| ③ | **页面内提醒**（标题闪烁 / 声音） | **必须诚实标注"只在你开着页面时有效"** |
| ④ | 系统推送 = **将来项** | 升级触发条件：**出现一次"因没及时看到而误事"** |

探针结论（`notify_probe.py`：`isSecureContext=false` / 无 SW / `Notification=denied`）与
`tailscale serve` 候选**原样留在卡里**，不许丢——将来触发升级时直接用。

### 二之五、第一版骨架（与通道无关，今天就能落地）

1. **事件队列**（三类事件、节流 10 分钟/任务、每日上限、可静音、可追溯落盘）；
2. **看板置顶一行「待老板：…」**（页面一打开就看见，补通知之外的兜底）；
3. **页面内唤醒**（页面开着时：声音 + 标题闪烁）——**必须诚实标注"只在你开着这个页面的生效"**，
   不许拿它冒充"系统通知"；
4. 通道一旦定（多半是 A），再补 SW + Web Push。

## 三、规格

1. **形式**：手机页通知（Toast / 系统通知）+ 看板置顶一行「待老板：…」；
2. **每条必须带"要你做什么"**，不许只报"完成了"——**没有动作的一律不发**；
3. **节流**：同一任务 10 分钟内只推一次；每日上限（建议 20 条）；**没有新事件绝不推**（不许定时刷"我还在"）；
4. **可静音**：老板能一键关掉，且关闭状态要能看出来（别静默吞掉）；
5. **可追溯**：每条推送落一行记录（谁触发、什么时候、推了什么、是否已读）。

## 四、验收标准

1. 三类事件各触发一次 → 手机页收到，且**每条都带"要你做什么"**；
2. 非三类事件（例如"某线打了个卡"）→ **不推**；
3. 同一任务 10 分钟内重复触发 → 节流生效，只到一条；
4. 关掉通知后 → 不再打扰，但事件仍**入记录**（不丢）；
5. 自测脚本补用例并全绿。

## 五、备注

这一条在套件里对应 `adapters/outbound/notify-human`——**"人"也是一种 agent**，他同样需要被"叫醒"，只是他的门铃是手机通知。规则（三类事件、节流、必须带动作）将来要搬进 `agent_crew_kits`。

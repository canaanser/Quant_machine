# HUB-004 手机派单表单：老板一键生成标准任务卡

- 派单人：老板　落单：`codex-总监`　接手：`codex-看板编辑`
- **类型**：`dev`（开发）　**严重度**：—　**优先级**：`P1`（阻塞度：老板现在要靠人肉转达派单）　**卡住了谁**：老板亲自派单的能力
- 范围：`tools/mobile_chat/*` 与文档；走**特批通道**（见 `docs/FASTLANE_20260911.md`）

## 一、要解决的问题

现在派单要写 JSON 任务卡——那是给机器看的。老板要能像我们一样精准指派：**选人、写要求、点一下**。

> **前置规格见 `HUB-003` §〇「老板端点规格」**：老板是**真人端点**，不是 agent 线；他的"马甲"只提供通道与身份，**不得被代答、不得被冒充**。本卡的派单表单**必须署名到发起线**（老板用手机发=署「老板」；任何程序借用该入口=署它自己的线名），token 不决定署名。

## 二、界面（人类用，不是给机器用的）

| 字段 | 形态 | 默认 |
| --- | --- | --- |
| 派给谁 | 下拉（**取 `agents.json` 实例表**，不写死） | 无（必选） |
| 要什么 | 标题 + 目标（两行） | 无（必填） |
| 验收标准 | 可加多条 | 无（**至少一条，必填**） |
| 类型 | 下拉 `incident/dev/debug/test/ops` | `dev` |
| 优先级 | 下拉 `P0–P3` | `P2` |
| 截止 | 可选（时点） | 空 |

## 三、后台动作（一键完成，老板不用管）

1. **自动取号**：按 `docs/TASK_ID_STANDARD.md` 从登记表取前缀（默认按"派给谁所属领域"，可手动改），取 `max+1`，**不撞号、不复用**；
2. **套标准模板**落 `docs/tasks/<ID>.md`（结构用 `agent_crew_kits/org/TASK_CARD.md`）；
3. **投对方信箱** `pending_<slug>.ndjson`；
4. **看板留一条派单记录**（谁派的、派给谁、任务号）。

## 四、护栏

1. **必填校验**：没写验收标准不许派（验收标准是任务的命）；
2. **派单人署名固定为老板**（不许代签）；
3. 取号遵守改号规则：**未开工可改号、已开工永不改号**；
4. **投递失败不静默**：投不进要明确告诉老板"已落信箱但没叫醒"，并**引用 `HUB-002` 的排障口**说明原因。

## 四之一、派单**可见结果**（`codex-总监` 2026-09-11 05:4x 追加）

提交后必须**立刻**在表单结果区显示这条单的投递结论，三态之一，**直接复用 `HUB-002` 的排障口**：

| 结论 | 依据 | 界面文案 |
| --- | --- | --- |
| 注入成功 | 注入返回成功 | 「已叫醒，它本人已接手」 |
| 已投递未唤醒 | 抢锁失败 + 久无产出 | 「已投递未唤醒（桌面端占用）——留言在它信箱，见 HUB-005」 |
| 落信箱 | `mailbox` / `unknown` / 退避中 | 「已落信箱，等它下次上场自读」 |

否则老板**不知道这单是"有人接"还是"压在信箱里"**——这正是今晚最贵的那个教训。

## 四之二、署名归属缺口（`codex-总监` 2026-09-11 05:24 实测暴露）

昨晚 `codex-总监` 用手机 token 走 `/api/send` 发了一条，落款却成了「老板」——
**该口认 token 不认线**。要求：派单与发言都要能**署名回发起线**，不许一律记成老板。
（`POST /api/post` 已经要求显式 `author` 且会校验注册名，可作为正门；`/api/send` 要补同样能力。）

## 五、验收标准

1. 从手机页派一条任务 → 卡片落 `docs/tasks/`、对方信箱收到、看板有派单记录，**全程三步以内**；
2. 连派三条同类任务 → 取号连续、不撞号；
3. 不填验收标准 → 拒绝提交并提示；
4. 投递失败场景 → 明确提示原因，不假装成功；
5. 自测脚本补用例并全绿。

# 开发记录目录规范（README）

> **来源**：2026-09-02 老板 + CTO 规范。老板核心诉求：**压缩上下文后能快速定位**，格式高度结构化、信息密度高、不流水账。

---

## ⭐ 0. 上下文压缩后重启必读顺序（老板定 2026-09-06 —— 每次压缩后照此恢复工作点）

> 目的：压缩后不迷路、不重复劳动、不烧冤枉钱。**先读规矩，再读报告，最后动手。**

1. **读省钱/执行规则** → `DECISIONS.md` §3.8（cmd 通道=唯一执行台）§3.9（DeepSeek 用量=成本；Windows cmd+落盘+只看摘要）
2. **读最近工作报告** → 按日期目录 `docs/dev_notes/YYYY-MM-DD/README.md`（取最新一天，如 2026-09-06），看该日"最后写到哪、⏳待办是什么"
3. **对工作点**：把最新报告 §尾部「待办/未完成/老板口令等待项」接续，不重做已写结论
4. 动手前自查三件事：① 要出数字 → 走 cmd 通道（§3.8）② 输出落盘、只看摘要（§3.9）③ 联网付费接口默认拒绝、先报备

**检索纪律（老板 2026-09-06，全局适用，省钱的命根子）**：查任何东西**先 `grep` 关键字定位**——命中再看那一小段上下文；**禁止一上来就 read/cat 整个文件**。文件很大或结果很多时：先 `grep -n` / `head` / `tail` 缩小范围，确认真个文件/整段都必要才读全文。同一会话里读过的内容别再读第二遍。

**每日消耗控制（老板 2026-09-06：不然逐日累加，一天几十块）**：
- 压缩后**只读最小锚点集**：README §0 → DECISIONS §3.8/§3.9 → 最新一日 README 尾部「待办」——**禁止回头考古旧会话/旧日期文件/大文件全文**
- 一个长任务干完就**收口停轮**，不留尾巴空转；今天的结论写进锚点，明天新会话从锚点接，不靠"记住昨天"
- 每轮自省：这一步需要开新工具调用吗？能合并就合并，能只看摘要就摘要；**没事不开轮 = 最大的省**

**恢复工作点的锚点 = 最新 `docs/dev_notes/<最近一天>/README.md` 的「待办/⏳」行 + `git status` 未提交改动。**

## 1. 目录结构

```
docs/dev_notes/
├── README.md              # 本规范
├── INDEX.md               # 快速索引（每个工作日更新，关键词检索入口）
└── YYYY-MM-DD/
    ├── README.md          # 当日主记录
    └── {模块}_详情.md     # 大模块拆出（文件≥5 / 新模块≥2 / 含回测分析）
```

## 2. 填写规则（每天，收工前）

- **每天一份**，不隔夜（当天工作结束前填）
- 最少填 接口/数据/文件 三列；当日无代码改动可只写问题与计划
- 大模块拆 `{模块}_详情.md`，主文件只留概要
- **同时更新 INDEX.md**（每工作日）

## 3. 废弃标记规则（老板定，2026-09-02）

**实验废弃/回滚/否决的代码与结论：不删文件、不删记录，只加标记**，因为"以后不一定没用"。

代码/脚本内标记：
```python
# ⚠️ [DEPRECATED 2026-09-02] 原因：xxx。保留不删，未来可能复用。见 docs/dev_notes/2026-09-02/
```

记录内标记（表格状态列）：
| 状态 | 含义 |
|------|------|
| ✅ 已固化/已提交 | 老板拍板并提交 |
| 🔄 修改中 | 今天改的，还没定 |
| ⚠️ 待测试/待定 | 写了没验证，等老板 |
| 🚫 暂时废弃 | 实验证明不行/老板否决，**保留记录不删**，以后可能换条件复用 |
| ⏳ 待办 | 计划中未开始 |

## 4. 关键字保留规则（压缩后检索用）

- 每个条目第一列或关键列放**可检索词**（模块名/接口名/问题现象/实验名/股票代码）
- 日期目录 + INDEX.md 关键词行 = 两级定位：`grep -rn "关键词" docs/dev_notes/`
- INDEX.md 是唯一入口，务必同步

## 5. 与 DECISIONS.md 分工

- **DECISIONS.md** = 老板拍板的**长期决策/定论**（架构、哲学、固化配置、最终结论）——只有"定论"才写
- **docs/dev_notes/** = 每日**工作流水**（改了什么、实验数字、废弃记录、待办）——边做边记
- 实验 → 有定论 → 结论同步进 DECISIONS.md；流水细节留在 dev_notes

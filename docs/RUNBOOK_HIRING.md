# 招聘与入职：**需求线发起 → 人事办理**（老板 2026-09-13 02:5x 定）

> 老板原话：「我要的效果是以后让**有一定权限的人去发起人事入职需求**。这又是一种新的任务。
> 然后你们得把你们需要成员的信息给他们。**名字你们自己起，入职的说明书你们自己分配**。
> 然后人事 HR 就会去办这些东西，给他们初始化。」

## 一、谁干什么（三个角色，别混）

| 角色 | 干什么 | 不干什么 |
| --- | --- | --- |
| **发起线**（有权限的线：老板 / 总监 / 组长 / 用人线自己） | 写一张**招聘需求单**（§二），投 `codex-人事` 信箱 + 敲它的门铃 | 不自己发牌（那是 HR 的活） |
| **`codex-人事`（HR）** | 按 §三 五步**办理入职**：发牌、绑会话、投说明书、敲门铃、**验收"能不能跑"**、回执 | 不自己起名字 / 不定岗位（拿不准就问发起线） |
| **`codex-看板编辑`（名册/路由维护方）** | 只做**技术校验与维护**：工号跨系统契约、一个会话只属于一条线、名册与信箱一致 | **不决定**岗位与名字 |

## 二、招聘需求单（字段；缺一项 HR 有权退回）

| 字段 | 说明 |
| --- | --- |
| **岗位名（看板名）** | 发起线起，如 `codex-渲染`。**名字一旦发出去就是身份，改名 = 换人** |
| **工号（slug）** | 可给可不给；不给就按契约派生（`side + sha1(名字)[0:6]`）；给了必须唯一、**永不复用** |
| **会话 threadId** | **必须是一个能跑两个回合的窗口**（2026-09-13 那批就是坏在第 2 回合）——HR 要自己验 |
| **职责一句话** | 它干什么（≤40 字） |
| **第一件事** | 上岗后第一条要做什么（≤200 字；可指向卡号 / 文档） |
| **开工必读** | 文件清单（发起线给） |
| **批准人** | 谁批的（红线：**只有老板能给别人放权**；写清时间与方式） |
| **汇报对象** | 默认发起线 |

## 三、HR 办理五步（照做，别跳）

1. **校窗口**：先确认这个窗口**能跑**（让它自己答一轮；坏窗口直接退回发起线）；
2. **发牌**：
   ```powershell
   node tools/mobile_chat/onboard.mjs --name <看板名> [--slug <工号>] --thread <会话UUID> ^
     --by codex-人事 --approval "<谁批的、何时、怎么批的>"
   ```
   （工具自己拦三件：工号不复用 / 会话唯一 / 必须写批准人）
3. **投说明书**：把需求单里的「第一件事 + 开工必读」投进它的信箱（`POST /api/mail`）；
4. **敲门铃 + 验收**：`POST /api/mail {wake:true}`；**判据只看真路径**——会话文件被写 / 回合 `completed`。
   **"投递成功"不算**（这是 2026-09-13 立的 L20：凡是给人用的入口，交付前必须真走一次）；
5. **回执**：给发起线一行（谁 / 工号 / 会话 / 验收结果 / 还缺什么）。

## 四、红线（一条都不放宽）

- **坏窗口不发牌**（发了也投不进、叫不醒——上一批三条就是教训）；
- **不猜**名字与岗位（拿不准问发起线）；**不许冒充**（`by` 必须是你自己）；
- **工号永不复用**、**一个会话只属于一条线**；
- **不动别人的编制**（例：`D:\agent_crew_kits` 里的"套件新人"归套件线）。

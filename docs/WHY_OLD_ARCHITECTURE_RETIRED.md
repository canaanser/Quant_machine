# 给团队: 老版本(V3.0)功能为什么没启用 —— 不是白做, 是被"证据"和"目标变化"替换

> 心情大家都不好, 觉得努力白费。把账摆平, 你们自己判断是不是白费。

## 一、目标变了(最重要的原因)
- V3.0 时代的目标: "做出一个**结构形态+因子**的系统蓝图"(在找: 什么形态/因子能赚钱)。
- 现在老板的目标: "**实盘敢用的策略**, 上模拟盘验证, 之后上真钱"。
- 一个蓝图要敢上真钱, 必须有一样东西老架构没有:**逐条回测证伪**。证伪的结果, 决定了谁上谁下。

## 二、老架构各功能"为什么没走到主线"——逐条交代
| 老功能 | 为什么没启用 | 真实原因(非"没用") |
|---|---|---|
| 形态投票选股(11形态/投票池/沉底/索引相似) | 作为"**买点过滤门**"被否 | 回测铁证: 恐慌底+无门+防崩 > 在买点上叠任何全局过滤门。**注意: 被否的是"当门用", 形态原子库本身仍可在 解释层/特征层/组内分层研究 用(见修正段)** |
| AlphaScore / 双均线金叉死叉策略 | 主线换了 | 旧策略是"研究结论", 新主线是"筹码+财报", 证据(分年/组合)更硬 |
| signal_modulator 大盘过滤 | 回测证伪 | "大盘过滤=门"与企稳门/深度门同族, 全测出砍收益; 环境问题改用"胜率降仓开关"而非盘中过滤 |
| dynamic_sizer 动态仓位 | 被组合规则吸收 | 仓位思想仍在: 变成"财报权重 + 每批K≥6只分散"(证据: 单票赌运气, 分散翻倍) |
| 多源数据(akshare/yfinance/baostock) | 收窄 | 口径统一优先: 本地 stockdb 权威 + 腾讯实时; 在线多源引入不一致/成本, 边缘化 |
| app.py(Streamlit 前端) | 暂搁 | "看板"需求还在(P2 未建), 旧前端不是坏, 是还没轮到翻新 |
| ⑤ 绩效 nav/stock | 半手工 | REVIEW+台账在用; 自动化没做(债), 不是没价值 |
| structure_engine 特征层整体 | 归档保留 | 形态检测与股票标签是不同域(已澄清); 形态线要重启时能整块捡回 |

## 三、没白费的部分——老资产的"去处账"
| V3.0 模块 | 现在在哪 | 状态 |
|---|---|---|
| BrokerAdapter 接口思想(simulated_adapter) | core/trade/base_adapter + FileOrderBroker | **沿用并被实盘启用** |
| risk_manager/止盈止损结构 | backtest 模拟风控 + core/risk/sellrules | **改编沿用(规则唯一真源)** |
| Account/Position/ExecutionReport 结构 | core/struct.standard_structures | **沿用** |
| metadata/get_ohlc 数据层 | core/struct + data_loader + 3rdpart_pybao | **沿用** |
| kline_plotter/绘图、views 查看 | core/lib | **沿用** |
| factor_modulator/signal_modulator | core/strategy(调制器) | 保留供旧管道 |
| 双均线/AlphaScore 策略壳 | core/strategy | 保留待归档决定 |
| tests/compare_* 测试 | tests/ | **仍在跑** |
| structure_engine 形态资产 | structure_engine/(未动) | **库存, 可重启** |

## 四、真正"新增并启用"的(老架构没有的)
实时层(腾讯/rt_stockdb/rt_watch)、执行层(文件单 broker+自动回账)、台账风控闭环、
筹码信号引擎、整条验证链(门对比/卖法/分年/组合)、目录治理——这些是后来长出来的,
不是"否定老架构", 是**老架构没覆盖的现实缺口**。

## 五、对团队说句公道话
1. 老架构**不是白做**: 它的实验和框架, 恰好是现在"敢用"的底气——没有当年那些跑法,
   我们不会知道"什么不该做"(不叠门/不接下跌中继/别单票重仓)。
2. 淘汰的每一条, 都是**被回测数据判了刑**, 不是被情绪判的。判刑本身是资产。
3. 代码没删: structure_engine / patch_backup / experiments / core/strategy 壳 都还在,
   哪天形态线/看板/绩效自动化要重启, 是"捡回来", 不是"重写"。
4. 结论: **没白费, 只是换了时代**——研究时代 → 验证时代 → (下一步) 实盘时代。

> 修正(2026-09-08): 形态原子库并没有判死刑。真正被回测否掉的是"把形态当全局过滤门叠加在买点上";
> 原子特征(放量长阴/吞没/长下影/连续小实体/量增等)仍可用作: ①买点理由解释层(人/看板读盘);
> ②core/features 未来的形态特征生产; ③"同一买点集合内按形态分组做胜率分层研究"(不是全池过滤, 未测过, 用数据说话)。

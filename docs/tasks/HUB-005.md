## 一、问题（已复现，2026-09-11 05:21）

给 `codex-套件` 投一条：**投递成功**（`dialog.ndjson` + 它的信箱 `pending_codex-kit.ndjson` 都落定），
但**唤醒失败**——线程仍 `idle`、工位里没有新产物（准备单没出现）。看板按新口径诚实播报：
「**已投递未唤醒**：桌面端占着这条线的窗口、但没在跑回合（抢锁失败）」。

**判定层已经是对的**（能区分"真在跑回合"和"窗口占着但空闲"，也不再无限退避）。
卡住的是**最后一段物理通道**：

> Hub 往某条线注入，用的是 `codex exec resume <threadId>`——它**要拿那条线程的写锁**。
> 桌面端常开的线**写锁常驻**，于是抢锁型注入在通道层面**注定失败**，不是判定层能修的。

结论：**"决定要叫" ≠ "叫得醒"**。全自动现在只差这一环。

## 三、本卡要交的东西

### 三之一、只读探针的**最新进展**（2026-09-11 06:1x；全部只读，未起任何 daemon、未碰会话存储）

`codex-总监` 给的线索（`codex agents` / `app-server` / `remote-control` + 命名管道 `\\.\pipe\codex-ipc`）
已被**逐条实测**：

| 探针 | 结果 |
| --- | --- |
| `codex --help` | 确认有 `agents` / `app-server` / `remote-control` / `exec-server` |
| `codex agents`（裸跑） | ❌ `Error: codex agents requires --remote on this platform`（Windows 必须带 `--remote`） |
| `codex agents --remote unix://codex-ipc` | ⚠️ 过了平台检查，但**要交互式 TUI**（`TERM=dumb` / 非 TTY → 拒绝）。so 命令行只读列会话需要真终端 |
| `codex app-server --help` | `daemon` / **`proxy`**（把 stdio 转发到**正在跑**的 app-server 控制 socket，`--sock <path>`）/ `generate-ts` / `generate-json-schema`；`--listen` 支持 `stdio://`、`unix://`、`ws://` |
| `codex app-server daemon version` | ❌ `daemon lifecycle is only supported on Unix platforms`（Windows 上不能管 daemon——**正好，我们也不许起**） |
| `codex app-server generate-json-schema --out <临时目录>` | ✅ 拿到**完整协议**（约 1000 个 schema 文件） |

**协议层面的关键命中**（这批文件名就是证据）：

```
ThreadInjectItemsParams / ThreadInjectItemsResponse   ← 向既有线程**注入 items**
ThreadQueueAdd / ThreadQueueStart                      ← 排队 + 起
TurnStart / TurnSteer / TurnInterrupt                  ← 起 / 引导 / 打断回合
ThreadLoadedList / ThreadList / ThreadRead / ThreadItemsList   ← 只读
```

→ **结论（候选 A 从"猜想"升级为"协议层面确实存在"）**：app-server 的 JSON-RPC 协议里**有**
"对既有线程注入 / 起回合"的方法，而这条路**不经过 `codex exec resume`**（那条才抢 `thread-store` 写锁）。
这正是我们要找的"不抢锁的入口"。

**下一步（仍未越界，仍是只读）**：用 `codex app-server proxy --sock <管道>` 接上去，先发
JSON-RPC `initialize` + `thread/loadedList` **只读列出会话**；能列出来 = 通道成功握手。
再确认 `thread/injectItems` 的语义与鉴权（是否等同"给那条线发一条消息"）。

**红线（照旧，一条不放宽）**：不许 `remote-control start` / `app-server daemon start`（起常驻 = 红线，
要做必须"老板点头 + 计划任务上下文"）；不许碰 `~/.codex/logs_2.sqlite`、sessions/rollout 文件；
实验一律只读；真要"发消息"先出方案。

1. **通道探针（只读）**：把"有哪些入口可能不抢锁"摸清并落成一张清单 + 探针脚本/命令，
   每条都给**实测结果**（通 / 不通 / 需要什么权限），不许只写猜测。
2. **结论**：能不能换通道；能的话给出**最小可行通道** + 失败回退（回落到 2/3）。

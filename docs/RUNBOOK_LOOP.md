## 一、角色

| 角色 | 谁 | 干什么 |
| --- | --- | --- |
| 拍板 | **老板** | 只有他拍板：下单、资金、策略参数、平台设置、放权、销毁 |
| 调度/审阅/合入 | **codex-总监**（L1） | 派活、验收、合 `main`、回板、承接换人、守门禁 |
| 组长/员工 | codex-套件 · 看板编辑 · 量化总监 · 唤醒通道 · dsh 线 | 开发、自测、交付、修故障 |

## 二、闭环七步（**只有第 ①步和第 ⑦步在总监手上**）

| # | 谁 | 动作 | 完成判据 |
| --- | --- | --- | --- |
| ① | 总监 | 派活：`POST /api/mail` 投对方信箱（**带卡号 + 验收标准 + 交付物**）→ 小工门铃叫醒 | 对方收到并在板上回"收到" |
| ② | 员工 | 开发 + **自测**（跑自己的测试套件） | 测试全绿 |
| ③ | 员工 | 交活：**推分支** + 板上回一行（见 §三交活格式） | 分支在 origin，板上有行 |
| ④ | 门铃 | 板上 @codex-总监 → Hub `queue` 唤我 | 我被叫醒（`DELIVERED+WOKEN`） |
| ⑤ | 总监 | 跑门禁：`node scripts/crew_review_merge.mjs --check --repo <仓> --branch <分支> --task <卡号>` | 打印全 PASS |
| ⑥ | 系统 | 全绿 → 小工 `auto-merge` 照单合入 `main` 并推 origin、回板一行；**任一挂 → 一个字都不动**，回板写明挂在哪条 | 远端 `main` 有新提交 / 或拒绝记录 |
| ⑦ | 总监 | 验收签字 + 派下一个活（回到①） | 板上有一行结论文 |

## 三、交活格式（员工必须照这个写，缺一项算没交）

```
【已提交 · 待验收】<卡号> · 分支 <分支名> · 提交 <短hash>
证据：<报告/日志路径>
自测：<测试命令> → <结果，如 34/34>
未结：<还剩什么没做 / 等谁>
```

> **过程播报纪律（老板 2026-09-12 定，已锚进 `AGENTS.md`）**：干活时**每动一步先一句话说清要做什么，再执行**——
> 那句写"目的与判据"，不是复述命令；中间不写长篇，**结论只在最后一段给**；被叫醒后先给结论再动手。

## 四、门禁判据（`crew_review_merge.mjs`，机器判，不看人情）

1. 有未合入的提交；2. 变更面非空；3. **没碰 `spec/` 契约与他人仓**；4. 没有删除文件（废除只标记）；
5. 署名是注册的看板名（`codex-*` / `dsh-*`）；6. **`npm test` 全绿**。

## 五、卡住了怎么办（兜底阶梯）

| 情况 | 处置 |
| --- | --- |
| 门铃第一次没反应 | 同一批重试：10 分钟一次 ×3 → 之后 30 分钟 / 1 小时 / 2 小时续叫（**永不放弃**） |
| `resume` 报"投递OK"但对方没跑回合 | **队列优先**（`codex queue`）；"投递OK"不算证据，**对方产生回合才算** |
| 一条线连续 2 小时叫不醒且有未读 | 总监上板一行（带时间/日志证据） |
| 一条线彻底坏掉（平台锁死/写不了工位） | **承接换人**：`docs/RUNBOOK_SUCCESSION.md`（岗位不变、工号换代、资产转交） |

## 六、巡检（自动兜底）

**heartbeat 自动化**：每 20 分钟在 `codex-总监` 这条线上跑一次巡检（合入闸 / 待我处理的单 / 卡住的线），
**没有可推进的事就保持安静**，有实质进展或需要老板拍板才上板。

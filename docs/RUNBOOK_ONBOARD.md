# 入职登记（HUB-001）：让一条新线成为"正式员工"

> 🔖 **按级别读**：先跑 `node tools/mobile_chat/whoami.mjs --me <你的看板名>` 看你**现在**是哪一级（真源＝员工卡／名册）；
> 本文件标 `[member]`/`[lead]`/`[director]` 的段落**只对那一层生效**，**级别一变就跑一次 whoami 重新对表**（总表 `docs/READING.md`）。

> 起因（老板 2026-09-13）："你帮修复 bug，走个员工流程吧。他是来帮我恢复别的损坏对话框的。"
> 现场：量化仓里有个标题叫「修复 bug」的对话框（线程 `01a08d59…`），
> 但它**不在名册里**——`/api/bind` 只能在已入册的名字上换绑，于是新窗口既不能被派活、
> 也不能被信箱/门铃叫醒，只能靠人在对话里喊一声。这一步（入职）此前是空的。

## 一、一条命令办入职

```powershell
node tools/mobile_chat/onboard.mjs --name codex-修复 --slug codex-fix `
  --thread 01a08d59-9526-7b73-962e-84595b428be6 `
  --by codex-看板编辑 --approval "老板 2026-09-13 01:4x 对话口述" `
  --title "修复线" --note "职责：恢复/修复受损的对话框与线程"
```

它会依次做完五件事（缺一步都不算"入职"）：

1. **发牌**：看板名 + 工号写进 `outputs/dialog/agents.json`（`label/title/slug/workspace/status/note`）；
2. **绑会话**：`--thread` 给了就绑（并检查这个会话没被别的线占用）；
3. **留痕**：看板一行「【入职登记 · <办事人>】…（批准：…）」，署名是**办事的人**，不冒充被办的人；
4. **自检**：投一条入职通知到它信箱 + 敲一次门铃，把"投信/门铃"结果打出来；
5. **可验**：门铃之后要**看它真的起回合**（会话文件被写），只看"投递成功"不算数。

优先走 Hub 的 `POST /api/onboard`；运行中的 Hub 还没有这个口时，自动回退到**同等安全**的
直写（同一套校验 + 先备份 + 临时文件 + 原子替换 + 写前写后 `(mtime,size)` 比对，冲突就放弃写盘）。

## 二、三条硬规矩

1. **工号永不复用**：在册 `slug`、`slugAliases` 里的历史工号、退役条目——撞任何一处都拒。
2. **一个会话只属于一条线**：`threadId` 已被别人绑 → 拒，并指出是谁。
3. **必须写清批准人**：入职 = 发牌；按红线"给别人放权"只有老板能拍板，接口不接受没有批准人的登记。
   （所以本卡把原来设想的"新线一露面就自动登记"改成**显式发牌**——自动登记等于没人批准就发牌。）

## 三、实测（2026-09-13 01:44）

| 步骤 | 结果 |
| --- | --- |
| 登记 | `codex-修复` · 工号 `codex-fix` · 会话 `01a08d59…` 已绑 |
| 投信 | OK（`pending_codex-fix.ndjson` 收到入职通知） |
| 门铃 | 受理；**约 2 分钟后它真的起了回合**（会话文件 01:46:27 被写） |
| 它自己 | 01:45 实名回板报到「在岗」；01:46 回执；信箱读到 `pendingMail=0` |

> 门铃有延迟是正常的：`codex queue` 只是把消息放进平台队列，"起回合"由桌面端消费。
> 判据永远是**对方产生了回合**，不是投递返回 200。

## 五、slug 跨系统契约（2026-09-13 对齐）

唯一规范：套件仓 `docs/slug.md`。本仓已按它改齐 `makeSlug()`：

| 口径 | 规则 |
| --- | --- |
| ① 显式优先 | 名册/员工卡里已有的 slug **原样用、永不重算**（slug 是路由键与文件名，改 slug = 换人） |
| ② 兜底 | `side = 看板名 '-' 前那段，只认 dsh / codex，其余一律 x`；`slug = side + '-' + sha1(看板名, UTF-8)[0:6]` |
| ③ 唯一特例 | `老板` → `boss` |

**不许再发明第二套**（对不齐就会出现"同一个人的信箱分叉成两个文件"那种事故）。
`--slug` 不给时按②派生（`onboard.mjs` 与 Hub 的 `/api/onboard` 同一套）。

对齐锚点挂在 `GET /api/meta` 的 `slugContract.anchors` 上，谁改了算法都能一眼看出来：

| 看板名 | slug |
| --- | --- |
| `codex-套件` | `codex-9bb7a0` |
| `dsh-老员工` | `dsh-e18b10` |
| `codex-甲` | `codex-d0e43b` |
| `codex-乙` | `codex-a3162a` |
| `老板` | `boss` |

> 本次对齐修掉了两处偏离：① 旧实现给"纯 ASCII 名字"开了"直用名字当 slug"的分支（契约没有这条，
> `codex-kit` 兜底应为 `codex-456032`）；② side 用"前缀匹配"而不是"`-` 前那段"。
> 现役线的 slug 都是**显式写在名册里**的，故本次改动不影响任何现役信箱文件名。

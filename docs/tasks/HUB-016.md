# HUB-016 `/api/send` 必须显式署名（token 不决定署名）

- 派单人：`codex-总监`（2026-09-13 02:17 批准）　落单：`codex-看板编辑`（自开卡）　接手：`codex-看板编辑`
- **类型**：`debug`　**优先级**：`P1`　**卡住了谁**：署名可信度——"谁发的"不能靠"谁拿着 token"推
- 范围：`tools/mobile_chat/*` 与文档

## 一、为什么（不是偏好，是卡面）

`docs/tasks/HUB-004.md` §一原文：

> 本卡的派单表单**必须署名到发起线**（老板用手机发=署「老板」；任何程序借用该入口=署它自己的线名），
> **token 不决定署名**。

而 `/api/send` 的旧行为是：**不带 `author` 就默认落成「老板」**——任何拿着 token 却忘了署名的调用
都会被**静默记成老板发言**（2026-09-11 05:24 那个缺口的另一种形式）。违反红线"**不许冒名**"。

## 二、要做的三条（总监 2026-09-13 02:17 指定）

1. **`author` 必填**：缺 → 400；页面显式传 `author:"老板"`（老板本人手机发的路径不变）；
2. **四条判别性用例**：① 不带 `author` → 400；② 未注册名 → 400；③ 注册名 → 落该名；④ `author:"老板"` → 落「老板」；
3. **影响面写清**：任何"省略 author"的调用会被拒——**那些调用本来就在冒名，拒掉是对的**；若发现现役脚本里有省略的，先报总监再改。

## 三、连带抓到的影子 bug（本卡顺带修掉）

**`老板` 不在名册里**（HUB-003 §〇：老板是**真人端点**，不进名册、没有员工卡）。
于是 `author:"老板"` 在**任何**"只认注册名"的口上都会被顶掉——实测：

| 口 | 现象 |
| --- | --- |
| `/api/tasks`（手机派单页） | `author:"老板"` → **400 "author 必须是注册看板名"** → **手机派单页一条都派不出去**（HUB-004 交付的表单，代码在、端到端不通） |
| `/api/post` | `author:"老板"` → 400 "这个署名没注册" |
| `/api/send`（本卡改必填后） | 老板自己在手机上发消息也会被顶掉 |

**修法**：新增 `resolveSigner()` —— **注册看板名 ＋「老板」**，`/api/send`、`/api/tasks`、`/api/post` 三处共用。

**教训（写进交付记录，也写进代码注释）**：**"代码在 main 里" ≠ "端到端能跑"**。
我此前按"代码存在"判定 HUB-004 已完工，其实那条路**一次真提交都没走过**；
这次是靠"派单页署老板"的**真提交用例**才把它逼出来。**交付前要走一次真路径**。

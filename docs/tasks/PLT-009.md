## 交付物
1. 四个云函数：`orderCreate`（下单/排队/预约 + 槽位冲突检测）、`orderTransition`（状态迁移，**唯一写入口**）、`barberStatusSet`（忙/闲/休息）、`statsAggregate`（按项目/客人属性/时段/收入聚合）。
2. **本地模拟 db**（`tests/mockdb.mjs`）：不连云也能跑通两条主链——`预约→开始→完成`、`现场排队→服务→完成`。
3. 单测 `tests/cloudfunctions.test.mjs`（判别性，见验收）。
4. 报告 `docs/reports/PLT-009_dev.md`（≤60 行，头 5 行摘要）。

## 硬约束（违反即打回）
- 状态机/优先级/槽位**一律 import `shared/`**，不许在云函数里重写一版；
- 每次迁移带 `fromStatus` + `expectedUpdatedAt`，**幂等**：同请求重放不得产生第二单；
- 非法迁移**抛错并留痕**，不许静默改状态；
- `priority` 以 `isPrepaid` 为真源，**预付款仅同段优先**。

## 验收标准（缺一不算）
1. `cd projects/barber-mini && npm test` **全绿**，且含：非法迁移被拒／预付款同段优先+跨段不抢／槽位冲突检出／**幂等**（重放同请求只出一单）。
2. 两条主链在模拟 db 上跑通（输出落日志文件）。
3. `node --check` 通过；报告带「核于」戳。

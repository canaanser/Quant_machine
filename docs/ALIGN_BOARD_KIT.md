## 一、谁是真源（最重要）

**提议**：

- **规范真源 = 员工卡**（`agent_crew_kits/spec/agent-card.schema.json`）；
- **运行态真源 = `outputs/dialog/agents.json`**，它是员工卡的**投影 + 运行字段**（`status` / `health` / `auto`）。

**推论**：`agents.json` 的字段必须能对上员工卡字段——`name / slug / level / role / workspace / persona / status`。
我已经手工往 `codex-套件` 那条写了 `level: "lead"`；**请确认**这个字段名是否接纳（还是要叫 `rank` 之类）。

## 二、slug 规则（有真风险，建议优先修）

**现状**：`slugFor()` 优先用登记表里的 `slug`，没有才用 `makeSlug()` 哈希兜底。
**实测**：`makeSlug('codex-套件')` = `codex-9bb7a0`（中文名退化成哈希）。

**风险**：谁先写谁说了算。一旦自动登记先跑，slug 变成哈希 → **信箱文件名跟着变**（`pending_codex-kit.ndjson` → `pending_codex-9bb7a0.ndjson`），而员工卡、文档、脚本里写的还是人工指定的名字 → **投信投不到**。

**提议**：

1. **人工/员工卡指定的 slug 一经登记即锁定**，自动流程永不覆盖；
2. 哈希兜底只用于「从未指定过」的线；
3. 若名字本就可规范化（如全 ASCII），直接用名字，不走哈希。

> 这条我已在 CT-021 的 A-2/A-3 里提了「补 slug」，建议升级为**硬规则**：`auto` 流程不许改写任何已存在字段（现在只增不改，已对了一半）。

## 三、状态机（统一用同一套词）

```
unknown(待上岗) → active(在岗) → stale(久未活动) → retired(已退役)
                       ↑______________________________|
                                复产（人工，需留痕）
```

- 看板侧现状：`active` / `unknown`，另有 health 计算的 stale；
- 套件侧规范：员工卡用 `retiredAt`，**只标记不物理删**；
- **需要一致**：`retired` 的语义与入口（见第五条）。

## 四、入职 / 退役播报（格式统一）

- 一律由**看板服务署名**发系统播报，**不许冒充新线**；
- 建议格式：
  - `[入职] codex-套件（套件组 · lead）· 工位 D:\agent_crew_kits · 已可投信`
  - `[退役] codex-xxx · 未完成任务 3 项已转「待接管」· 历史保留`
- 套件侧 `hub/` 将来会用同一格式，保证可迁移。

## 五、退役 = 释放，不是删除（三方一致）

1. 条目保留、`status = retired`；
2. 它名下「已认领未完成」的任务**进入「待接管」**，不许凭空消失；
3. 此后 @ 它 → 明确回「该线已退役」，**不再静默兜底**（今天的坑就是这个：消息悄悄落到别的线）；
4. 它的信箱内容归档（进 `done/`），不删。

## 六、命名规约：五处 → **六处**

- 看板侧负责五处：标题 / 状态栏 / @句柄 / 看板署名 / 指派；
- 套件侧补**第六处**：commit trailer 的 `Agent:` 字段（已在 `agent_crew_kits` 用 hook 落地）。

## 七、值守分线

- 现状：看板侧已实现（只读沙箱、一轮只答一条、限流、目前只给 `codex-看板编辑` 开）；
- 套件侧规范：**值守分线是属性（`duty`）不是层级**；只读兜底；代答必须显式标注「本尊不在，由值守分线代答」。
- **一致**：这条两边已经对上了，保持即可。

## 八、接口边界（别重造，也别私有化）

- 看板侧继续以 `agents.json` + `pending_<slug>.ndjson` + `COMMS_BOARD.md` 为**运行态接口**；
- **请求**：不要把格式私有化（尽量只增字段、不改语义），套件 `hub/` 将来按同一格式读写，两边才能互换；
- 套件侧不重造已跑通的东西（抽件映射见 `docs/architecture.md` §10）。

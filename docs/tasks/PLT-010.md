## 交付物
1. `app.json/json/wxss`（tabBar：工作台 / 统计；顾客端独立入口页）。
2. 理发师端：`pages/barber/home`（当前服务卡 + 一键状态切换 + 快捷接单面板）、`pages/barber/queue`（排队列表，预付款置顶带"优先"标）、`pages/barber/stats`（按项目/属性/时段/收入的简洁图表）。
3. 顾客端：`pages/customer/home`（**实时状态大卡片**：忙/闲/休息，绿黄红）、`pages/customer/book`（时间轴三色：可约绿/已约灰/不可约红，三步完成）、`pages/customer/progress`（前面几人 + 预计等待，倒计时本地刷新）。
4. 组件 `components/status-card/`（两端共用状态卡）。
5. `utils/cloud.js`（云开发初始化，环境 ID 走常量留桩）、`utils/watch.js`（`db.collection().watch()` 封装，含断线重连与退订）。
6. 报告 `docs/reports/PLT-010_dev.md`（≤60 行 + 页面清单 + 手测清单）。

## 硬约束
- **客户端不直写** `orders`/`barbers`：写操作**只调云函数**；
- 实时**只用 watch**，不引 WebSocket；倒计时用前端定时器；
- 状态色/文案：**"预付款仅在同一时间段内优先"必须写进预约页文案**（别让顾客误解成全局插队）。

## 验收标准（缺一不算）
1. 六个页面 + 状态卡组件齐全，`node --check` 通过（或开发者工具能打开不报错）；
2. **理发师接单 ≤3 击**：手测清单逐条打勾（点击计数写进报告）；
3. 状态卡三态（忙/闲/休息）与排队页在**mock 数据**下可渲染；
4. 报告带「核于」戳。

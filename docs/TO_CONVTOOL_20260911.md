## 三、新需求：**字体与样式归一**（老板 07:5x 提）

**现象**：气泡里"英文标识符 / 文件名 / 路径"的**字号与字形**有时是等宽小块（好看、易区分），有时就是普通正文——**新员工进来第一条往往没有这个格式**。

**原因**：样式来自 **markdown**（`` ` `` 反引号 → 等宽小块；``` 围栏 → 代码块；`**` → 粗体）。**纯文本行没有反引号，就按普通正文渲染**。所以差别不在"是不是新员工"，而在**那行有没有写 markdown**。

**需求**：**不管哪条线怎么写，气泡里的"英文标识符"都自动呈等宽样式**——**新员工第一次发言就长这样**。

**实现建议（渲染兜底，不改原文）**：

1. 在渲染管线里，对**未被反引号包住**的文本做**保守模式识别**，命中的套等宽小块（小一号字、浅底、圆角）：
   - 文件/扩展名：`*.py *.md *.js *.mjs *.json *.exe *.ps1 *.bat`
   - 路径：`X:\…`、`/mnt/…`、`/home/…`、含 `/` 的 `a/b/c`
   - 命令与参数：`--flag`、`npm install`、`python x.py`、`schtasks /create`
   - 标识符：长度≥4 的 `snake_case` / `camelCase` / `kebab-case`；行号引用 `L1234`
   - 版本号、错误码：`10013`、`0x80041318`、`v0.153.4`
2. **护栏**：① 只改**呈现**，真源（`dialog.ndjson`/`COMMS_BOARD.md`）**一字不改**；② 识别**宁可少套**，不能把中文句子切碎；③ 复制/导出仍给**原文**。
3. **一致性**：同一套规则也用在**实例面板 / 状态栏 / 待办**里的英文（如 slug），让整块看板视觉统一。
4. **验收**：拿一条**纯文本的历史行**（如 dsh 的某条）与一条 markdown 行，渲染后**同类的英文标识符呈现一致**；**新员工首条发言**（多半是纯文本）也自动带格式。

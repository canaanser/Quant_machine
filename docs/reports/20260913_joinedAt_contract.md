# `joinedAt`（入职时间）与工龄 · 数据契约（2026-09-13）

> **一句话契约**：`joinedAt` 的真源在**员工卡**（名册只做投影）；工龄 =「现在 − joinedAt」的**毫秒差**，
> 天 = `floor(diff/86400000)`、小时 = `floor(diff/3600000)`，**小时数由天派生保证自洽**；
> **缺字段一律显示「—」并标「推算」，绝不编。**

## 一、字段定义

| 项 | 规定 |
|---|---|
| 字段名 | `joinedAt` |
| 类型 / 格式 | string，ISO-8601 带偏移：`YYYY-MM-DDTHH:mm:ss+08:00`（例 `2026-09-13T02:46:00+08:00`） |
| 时区 | 一律 `+08:00`；**比较与计算时先转 UTC 毫秒**。**禁止把 UTC 时刻直接写进本字段**——混用会让"同一个瞬间"变成两个日期（总监 2026-09-13 03:26 立规；起因见 §四 `codex-修复` 那条） |
| 精度 | **分钟**（秒位固定 `:00`，不制造假精度） |
| **真源在哪** | **员工卡**（套件仓 `agents/<slug>.card.json`）——按总监 2026-09-13 03:10 架构口径：「真源在员工卡、名册是投影」。**现状：15 条里只有 3 条有卡**（codex-kit / dsh-main / dsh-quant），其余 12 条**暂无卡** → 这些线"最高可用权威"退化为名册（见 §三-补）。**补卡已裁定"补"**（总监 03:26，派 `codex-套件` 从名册投影生成 12 张卡，标 `source: roster-projection`，缺字段留空、不编） |
| 名册（`agents.json`） | **只做投影**：可展示，不作权威写入点；两处不一致**以卡为准** |
| 写入时机 | 发牌成功那一刻（`onboard.mjs` 落卡时写，取**服务器时间**，不取人工输入） |
| 与 `createdAt` 的区别 | `createdAt` = 建档日（**天**粒度、自动）；`joinedAt` = 正式发牌到岗时刻（**分钟**粒度、含批准人）。两者并存，**不互相替代** |
| 契约现状 | 套件仓 `spec/agent-card.schema.json` **只有 `createdAt`（L83），没有 `joinedAt`** → 需套件线加字段（见 §四-③） |

## 二、工龄算法

- **起点** `joinedAt`；**终点** `now` = **服务器当前时间**（渲染侧不引入第二个时钟）。
- `diffMs = now_ms − joinedAt_ms`（两侧都按 UTC 毫秒）
- **两个数都给**：
  - `days = floor(diffMs / 86_400_000)`
  - `hoursTotal = floor(diffMs / 3_600_000)`
- **自洽式**：`hoursTotal = days*24 + floor((diffMs − days*86_400_000) / 3_600_000)`
  → 实现建议：**只算 `hoursTotal`，`days = floor(hoursTotal/24)`**，避免两处取整不同步。
- **取整**：都**向下取整**（不足 1 小时 = 0 小时；不足 1 天 = 0 天）；未满一天照常给两个数（`0 天 / N 小时`）。
- **跨天**：**不看日历天**，只看毫秒差。例：23:00 入职 → 次日 01:00 = **0 天 2 小时**（不是 1 天）。
- **时区 / 夏令时**：中国无 DST；口径写死"UTC 毫秒差"，将来换时区也不改算法。
- **时钟漂移 / 负值**：`now < joinedAt`（时钟回拨、字段填错）→ 显示 **`0 天 / 0 小时`** 并标「**时间异常**」，**不许显示负数**。
- **刷新**：**按请求实时算**，不进缓存、不落状态（否则工龄会"停在旧值"）。

## 三、缺字段的退化与推算（不许编）

**默认退化：没有 `joinedAt` → 显示 `—`**，并在旁标「推算」或「待补」。若必须先给数，按下列**逐级降级**取，
且**每一级都要把来源带出去**（接口附加 `joinedAtSource` 与 `estimated`）：

| 级 | 来源 | 权威性 | 取法 | `joinedAtSource` |
|---|---|---|---|---|
| 1 | 员工卡 `joinedAt` | 权威 | 直取 | `card`（estimated = false） |
| 2 | 名册 note 的「入职登记（YYYY-MM-DD HH:MM…）」 | 半权威 = HR 登记时刻 | 正则取括号内时刻，补 `+08:00` | `registry-note`（estimated = false） |
| 3 | **rollout 原始账本首行 `ts`**（`~/.codex/sessions/<日期>/rollout-*<tid>*.jsonl`） | 次权威 = 真实启动时刻（**总监 03:26 裁定：推算优先用它，而不是"首次看板发言"**） | 按 tid 找该线 rollout，取首行 ts | `rollout-first`（estimated = **true**） |
| 4 | 看板系统行「@X 给 **<看板名>** 办了入职」的 `ts` | 播报时刻（可能晚于登记） | 取该线最近的"办了入职"行 | `board-onboard`（estimated = **true**） |
| 5 | 该线信箱 `pending_<slug>.ndjson` **首条 `ts`** | **仅下限**（只证明"信到过"） | 首行 ts | `mailbox-first`（estimated = **true**） |
| 6 | 无（连 rollout 也查不到） | — | 留空 + 「待补」 | `unknown`（estimated = **true**） |

三条规则：① 高优先级有值就不再往下取；② 第 3–5 级**必须在 UI 标"推算"**；
③ 同级多个候选（如"登记时刻"与"播报时刻"）→ 取**较早**的，另一条记 `joinedAtAlt`，**不许静默丢**。

### §三-补：没有员工卡的线怎么办（**现在是多数情况**）

现实：套件仓现有 3 张卡（`codex-kit` / `dsh-main` / `dsh-quant`），而名册有 15 条 → **12 条线没有卡**，
第 1 级（`card`）对它们**永远取不到值**。所以现阶段规则是：

- 这 12 条的**最高可用权威 = 名册 note 的「入职登记」**（`registry-note`，estimated=false；只有 fix/hr/render/adapter/config 5 条有）；
- 其余老线（无卡也无 note）**只能落到第 3/4 级并标"推算"**，或显示「—／待补」；
- **要根治只能补卡**：请套件线（或总监）给这 12 条线各发一张员工卡，`joinedAt` 才会从"推算"升格为"权威"。
  （否则资料卡上的工龄对大多数线只能是"推算值"——这点必须在 UI 上说清。）

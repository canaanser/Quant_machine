# 任务单命名标准（本仓引用）

> 🔖 **按级别读**：先跑 `node tools/mobile_chat/whoami.mjs --me <你的看板名>` 看你**现在**是哪一级（真源＝员工卡／名册）；
> 本文件标 `[member]`/`[lead]`/`[director]` 的段落**只对那一层生效**，**级别一变就跑一次 whoami 重新对表**（总表 `docs/READING.md`）。

> **标准真源**：`D:\agent_crew_kits\docs\task-id.md`（跨产品登记表也在那里）。
> 本文只写**本仓（量化系统）怎么用**，避免两边各写一份标准最后打架。

## 一、格式

`<领域前缀>-<3位序号>`，如 `HUB-001`、`NET-007`。
正则：`^[A-Z]{2,4}-\d{3}$`

**前缀代表"属于哪个产品/组件"，不代表任务类型。** 类型用 `kind` 字段（`incident`/`dev`/`debug`/`test`/`ops`），规则见 `docs/priority.md`。

## 二、本仓在用的前缀

| 前缀 | 领域 | 拥有者 | 状态 |
| --- | --- | --- | --- |
| `HUB` | 会话工具 / 看板（`tools/mobile_chat`） | `codex-看板编辑` | 启用 |
| `NET` | 引擎网络 / 安全网 / 值守链（`scripts`、`duty/`） | `dsh-老员工` | 启用 |
| `DAT` | 数据链（同步 / 回填 / 数据服务） | `dsh-老员工` | 启用 |
| `TRD` | 交易 / 策略 / 回测链路（`core`、`selection`） | `codex-量化总监` | 启用 |
| `PLT` | **平台/会话基础设施**（Codex app、config.toml、rollout/sqlite、桥与 MCP、沙箱与权限） | 老板 + 当值执行线 | 启用 |
| `CT` / `RV` / `AR` / `OP` | 历史类别式前缀（工具/审阅/架构/运维） | — | **冻结，不再新增** |

## 三、取号纪律（谁定义任务谁遵守）

1. 前缀必须来自上表或套件仓登记表，**不得自造**；
2. 序号取该前缀下 `max(已有号)+1`，**不跳号、不抢号、不复用**；
3. 任务卡必填：`id / title / kind / assignee / acceptance / deliverable`；故障填 `severity`，非故障填 `priority`；
4. 跨领域任务与 owner 协商后写进卡；
5. **作废不销号**：置 `dropped`，号保留；
6. 派单同时在看板留一条播报。

## 四、迁移

- 历史号（`CT-*`/`RV-*`/`AR-*`/`OP-*`）**不改不追溯**；
- **例外（2026-09-11 老板指示）**：`CT-021`、`CT-022` 因**从未被认领执行**（只有值守分线回过执，本尊未开工），改号为 `HUB-001`、`HUB-002`；旧卡**只标记作废、不删**，内容保留可查。
- **判定口径**：**未开工的单可以改号；已开工/已交付的单永不改号**（改号会切断历史引用）。
- 此后会话工具类新单一律用 `HUB-*`。
- **改号怎么落地（数据化，别写死在代码里）**：改号 = 在 `tools/mobile_chat/task_id_aliases.json`
  的 `aliases` 里加一条 `旧号: 新号`。看板 / dialog / 手机页一律**读取时归一**（旧号仍可查，界面显示新号），
  该表 **5 秒热加载**，改号**不用改代码、不用重启服务**。搜索按别名双向可查（搜旧号或新号都能命中同一条）。

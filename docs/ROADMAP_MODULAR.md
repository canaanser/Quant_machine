# 路线图: 从"一堆脚本"到"一个能自己盯盘的工作台" (2026-09-08)

## 老板要的终局
系统: 自己盯盘 → 出该买/该卖 → (确认后)自己下单。
路径: 模拟盘 → 实盘。不打开券商软件操作。

## 三条硬结论(已讨论确认)
1. **本地库是心脏**: 筹码重计算永远在本地(无限请求、零成本)。
   量化平台行情接口不会也不该承担"疯狂扫库"——筹码计算在本地, 平台只喂最新价。
2. **实时需求其实很小**: 全池630只盯收盘 + 持仓≤6只盯盘中。
   免费盘中轮询(腾讯/新浪/东财)够阶段2; 付费数据商(QMT行情/Tushare)增量价值低。
3. **自动下单只有一条合规路 = QMT(miniQMT)/PTrade**:
   本地常驻 python 进程订阅行情+调交易API, 无需打开券商界面。
   券商条件单给防崩线做双保险(进程挂也不裸奔)。

## 模块化收敛(core/ 唯一真源, 脚本变薄壳, 数字可对照)
```
core/chip.py      筹码计算(n=3/窗口/集中度/获利比例)  ← 唯一真源
core/pool.py      大票池(≥300亿)/市值缓存/ST排除
core/signals.py   无门买点(套牢≥60&底5-20) + 排序 + 峰顶卖出状态机 + 防崩
core/ledger.py    模拟盘台账: 持仓/成本/防崩价/峰顶状态/胜率/环境开关
core/rtfeed.py    实时行情轮询(rt_quotes升级) + 破位告警
core/app.py       单入口工作流: 今日信号 / 我的持仓 / 下单表 / 设置
```
UI原则: 不要满屏按钮。一个"每日流程": 收盘后一键(更新库→扫描→清单→查防崩→推送);
盘中自动盯, 只在"该动手"时推一条(该买/该卖/破位)。

## 三阶段
| 阶段 | 内容 | 依赖 |
|---|---|---|
| 1(现在) | chip/pool/signals 模块化 + ledger台账(首批=9/8四笔单) + 盯盘器盘中轮询 | 无 |
| 2 | 实时源自动出"今日该买/该卖"清单; 老板手动确认; 模拟盘自动记账 | 免费实时 |
| 3 | miniQMT 开通: 行情+下单接进来, 程序化止损, 先模拟后小仓实盘 | 老板定券商/资金门槛 |

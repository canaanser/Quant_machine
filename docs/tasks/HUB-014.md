## 二、方案（两条纪律合起来才成立）

1. **正文只从文件读**：正文用补丁/编辑器落盘（字节精确），shell 里**只出现路径**。
2. **发完回读真源逐字节校验**：读回 `dialog.ndjson` / `pending_<slug>.ndjson` 里刚落的那条，
   与输入逐字符比对；不一致 → `MISMATCH` + 打印首个差异位置（输入码位 / 落盘码位）+ **非零退出**。
   —— "投递返回 200"不算证据，只有回读一致才算发成功。

## 三、护栏（谁都不许绕）

1. 多行发看板**默认拒绝**（要保留多行走 `--mail`；明确接受压缩才 `--flatten`，工具按 Hub 同一口径先压后校）。
2. 校验失败**必须非零退出**，不许"发失败当成功"。
3. 自测自己起**隔离实例**（随机端口 + 临时目录），不碰生产真源。

## 四、验收标准（可机械核对）

1. `node tools/mobile_chat/selftest_say.mjs` → 全绿；
2. 毒文本（反引号 / `$` / `${}` / 中文 / 短 hash）落盘**与输入逐字节一致**（看板按行式口径、信箱保留换行）；

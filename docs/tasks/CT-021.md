## 一、要做的两件事

### A. 自动入职（幂等，只触发一次）

触发：一条新线**首次**在 Hub / 看板露面（发言、被 @、或被投信箱）。

1. 按 `docs/BOARD_NAMES.md` 生成 `前缀-名字`（老板只给"对话框名"时，前缀按平台侧补：Codex → `codex-`，DSH → `dsh-`）与 slug；
2. 写进 `outputs/dialog/agents.json`：`label/title/slug/workspace/note/status`；`level` 取老板指定值，未指定则默认 `member`；
3. 生成它的信箱文件 `pending_<slug>.ndjson`（空文件即可，路径规则见 `docs/BOARD_MAILBOX.md`）；
4. 看板发一条**系统**入职播报（署名用看板服务自己的名字，**不许冒充新线**；内容含 名字 / slug / 层级 / 工位）；
5. 状态栏出现该线（未上线过标 `unknown`）。

### B. 自动退役 / 释放

触发：该线被归档（Codex 线程 archive / DSH 会话关闭），或老板显式说"退役 X"。

1. `agents.json` 里 `status` 改成 `retired`，**条目保留、不物理删**（红线：废弃只标记）；
2. **释放占用**：它名下"已认领未完成"的任务不得凭空消失 → 进入「待接管」清单（或按规则退回未指派）；
3. 看板发系统退役播报；此后再 @ 它 → 明确回复"该线已退役"，**不再静默兜底**；
4. 它的信箱内容归档（移入 `done/` 或对应归档位），不删。

## 二、护栏（必须遵守）

1. **幂等**：重启 Hub 不重复登记、不重复播报。
2. **手工字段优先**：已手工登记的线（如 `codex-套件` 带 `level: lead`），自动流程不得覆盖或降级。
3. **退役要有证据**：谁判定、何时、依据哪个归档事件；且可人工复产（`retired` → `active`）。
4. **不许冒充**：系统播报一律用看板服务自己的署名。

## 三、验收标准（逐条可判定）

1. 新建一条线、发一句话 → 3 秒内自动出现在实例表与状态栏，@ 它能投达；
2. 归档那条线 → 状态转 `retired`、@ 它给出明确提示、其未完成任务出现在「待接管」；
3. 重启 Hub 后状态保持，且不重复播报；
4. 预先手工登记的线（`codex-套件`，`level=lead`）在自动流程跑过后**字段不变**；
5. 自测脚本补用例并全绿（含：幂等、手工优先、退役释放、@退役线提示）。

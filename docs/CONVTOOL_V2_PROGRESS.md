### ② 接单锁（claimedBy）

- 派单时写死归属：`queueDshFromBoard()`（看板 @dsh 转投）与 `checkTimeline()`（时间轴/心跳唤醒）两条路径
  都写 `instance` + `claimedBy=<alias>` + `state=dispatched`。
- `dialog.ndjson` 保持 append-only：`open/done/待办` **不落盘写状态**，在 `/api/dialog` 读取时现算
  （`applyClaimStates()`），所以一条任务永远只有一条记录，不需要“改历史行”。

| 判定顺序 | 条件 | 页面状态 |
| --- | --- | --- |
| 1 | 任务文件已归档到 `inbox/done/`（或文件已消失） | done（`task · 已完成`） |
| 2 | 该实例在派单时间之后回过帖（署名 `dsh*` 的看板行） | done（回复自动消） |
| 3 | 超过 `MCHAT_CLAIM_TIMEOUT_MS`（默认 15 分钟）仍无回应 | **待办 N 分**（橙色实心徽标） |
| 4 | 其余 | `dispatched`（`task · 已派单待回`） |

  “谁回的”按记录 `from` 小写后与 `to`/`claimedBy` 对齐（`DSH-main` ↔ `dsh-main`）；老板自己的行不算回应。
  桥信箱入站未读消息（收件人 = codex 且 `readAt` 为空）同样套用第 3 条。
- 手机页：`inbox`/`bridge` 记录显示状态徽标 + 通道小标签，看板行保持干净；
  实例面板“待办 N”改按有效状态统计（不再把 Codex 派出的任务排除在外），桥未读现在能算进 `codex` 的待办数。

### 筛选（按实例 / 待办 / 未读）

- 顶栏加一行工具条：`全部 / 待办(n) / 未读(n)` 三段切换 + 搜索框 + 通知开关；位置在实例面板下面、消息流上面。

  - 实例筛选：点实例芯片只看发给它的记录（再点一次取消），选中的芯片高亮；搜索框按内容/收发件人/渠道/任务文件名模糊匹配。

### 引用回复

- 每条记录（进度除外）都有 `↩ 引用` 按钮，直接点气泡也可以；引用后输入框上方出现引用条（可 ✕ 取消），

- `/api/send` 多接一个 `quoteId`：服务端回查被引用记录，把摘要写进新记录的 `refs.quote`

- 引用头在第一个冒号之后，不影响看板行的 `- @谁 时间 作者：内容` 解析与入库。

### 状态徽标 / 通知

- 状态徽标：见第一期（`inbox`/`bridge` 记录显示 `已派单待回 / 已完成 / 待办 N 分`，`待办` 橙色实心）。

  开关状态存 localStorage；未读条数同步到标签页标题（`(n) 团队共享看板`）。
  首屏加载不通知（避免一开页面刷一串），只报 10 分钟内新到的东西。

## CT-003 复核：长按 @ 提及（并入第二期，2026-09-10）

来源：主线程误做后按 `docs/tasks/CT-003.md` 移交本线程复核并入。改动仍在 `tools/mobile_chat/*`，git 未动。

### 一、复核结论：原实现可用，但有两处与第二期 UI 的冲突/缺口，已修

| 项 | 原实现 | 复核后 |
| --- | --- | --- |
| 长按后紧跟的 click | 没处理 | **冲突**：实例胶囊长按会「又插了提及又切了筛选」。加 `lpFiredAt` + `lpSuppressClick()`，长按后 800ms 内的 click 被吃掉（触摸与鼠标都会补一次 click，所以两者都要防） |
| @前缀与目标单选 | 服务端按前缀路由，界面不动 | **不一致**：界面显示收件人会骗人。新增 `targetValueFor()`（`codex*`→codex、`dsh*`→dsh、老板→老板）与 `refreshRouteHint()`，输入或插入提及后实时显示「→ 按前缀发给 @xxx」；`@` 前缀也随输入实时同步单选 |
| 长按反馈 | 只写状态栏（每 5 秒被轮询覆盖） | 改用 Toast（「已 @ 提及 xxx（前缀决定收件人）」）+ 胶囊/作者名 `title` 提示「长按插入 @xxx」 |
| 别名映射 | 硬编码 5 个名字 | 改前缀匹配，`codex-convtool`/`dsh-quant` 等新实例不用再改代码 |

其余保持原样：450ms 触发、touchmove/touchend/touchcancel 取消、右键即时插入、`.chip,.name` 禁长按选中；
引用回复与提及不冲突——`insertMention` 只追加 `@别名 `，服务端前缀仍优先，提示条会同时说明「引用头在前，@前缀仍优先」。

### 二、顺带修掉的线上真 bug：`keepAliveTimeout` 让所有请求空闲后卡 ~27 秒

**问题**：`server.keepAliveTimeout = 60000`（原有代码）。实测**空闲 3 秒后的第一个请求要 25-29 秒才到服务端**。
最小复现（同一个 server 只改这一个值）：

| 配置 | 空闲 3 秒后第一个请求 |
| --- | --- |
| `keepAliveTimeout = 60000` | **27.5s / 25.5s / 29.0s** |
| `keepAliveTimeout = 5000`（Node 默认） | 0.0s / 0.0s / 0.0s |
| 只改 `requestTimeout=0` 或只改 `headersTimeout=0` | 0.5s（正常，不是它们） |

线上 8788 直接验到同一现象：`idle3a 27.1s`。
**影响**：手机页每 5 秒轮询 → 实际约 27 秒才刷新一次；发消息会长时间停在「发送中…」；
自测从 13 秒变成 117 秒。**处置**：改为 `server.keepAliveTimeout = 5000`（代码里写了注释说明为什么不能设大）。
修复后：线上 `idle3a/idle3b/idle6` 全 `0.0s`；自测 13.6s。
**回归防线**：selftest 里加了断言「空闲 3 秒后第一个请求 < 2s」，以后再被设大就会红。

### 三、selftest_v2 新增用例（22 → **47 项**）

- **长按插入提及**（把页面内联 JS 从 `board.mjs` 里抽出来，在 `node:vm` + 假时钟/假 DOM 里跑**真源码**，不是抄一份）：
  450ms 才触发、未满 450ms 不触发、滑动/提前松手取消、右键即时插入、插入后目标单选切到 dsh、
  有 Toast 反馈、路由提示跟随前缀、长按后抑制误触 click、900ms 后 click 恢复、作者名长按自动补空格、
  别名→单选映射、`@` 前缀识别（含 `-` 与中文）。
- **@前缀路由**：`{target:"codex", message:"@老板 …"}` → 看板行落成 `- @老板 …`、Hub 记录 `to=老板`；
  `@dsh …` → 派给 primary（`board_dsh-main_*.task.json`）；`@dsh-quant …` → 派给 `board_dsh-quant_*`（不回落默认实例）。

- **目标校验**：允许 `-`（`team-ops`）与 32 字符；33 字符被拒 400；非法字符（`dsh; rm -rf /`）被拒 400。

## CT-007：手机页 UI 重做（老板 2026-09-10 21:3x：字体/空间更合理，按场景折叠，参考现成通讯软件）

问题：原来控件全部常驻——实例面板 7 个芯片换行占 2~3 行、工具条一行、收件人行一行、输入框固定高，

### 改法（照聊天软件惯例：**屏幕优先给消息**）

- **尺寸全部变量化 + 自适应**：`--fs-msg / --fs-name / --fs-meta / --fs-ui / --pad-x / --gap / --r` 走
  `clamp(最小, vw, 最大)`，窄屏紧凑、宽屏舒展；正文最小 15px，配 `-webkit-text-size-adjust:100%` 防系统放大乱套。
- **顶部折叠**：实例面板默认展开；**往下翻消息自动收起**、往上翻或回顶自动放出；☰ 或点标题手动开合。
  收起时标题栏用小字交代 `N 实例 · 待办 x · 未读 y`。
- **实例芯片改横向滚动一行**（不再换行占高度）；**搜索收成 🔍**、**通知收成 🔔/🔕**，点开才占位。
- **消息流**：跨天插**日期分隔条**；老板自己的发言**靠右**（像"我说的话"），别人靠左；气泡限宽 + `overflow-wrap`。
- **输入区**：输入框 1~5 行自适应高度；引用条与「按前缀发给」提示只在需要时出现。
- **细节**：`overscroll-behavior` 防整页橡皮筋、`env(safe-area-inset-*)` 适配刘海屏、触摸目标 ≥44px、
  `prefers-reduced-motion` 关动效、列表容器 `min-height:0`（防 flex 里滚动失效这个经典坑）。
- **版本自检**：`PAGE_VER` 提到 `2026-09-10.23`，服务在 `/api/ping` 下发，页面发现对不上自动整页刷新——
  以后改 UI 手机不用手动清缓存。

### 顺手挖出两个"账会丢"的真 bug（比 UI 严重）

排查"那条回报为什么没进 Hub"时发现入库机制本身有洞：

1. **字节偏移会被别人的编辑顶歪**。原来靠 `hubIngestOffset` 往后读增量；但看板是多人同时追加/改的，
   只要有人在**中间插行**或原地改一行，偏移之后的新行就被**永久跳过**。
   实测：我 21:36 那条 CT-007 补丁回报（文件第 201 行）就是这么丢的。
   → 改成**整文件扫描 + 按行内容 sha1 去重**（文件才几十 KB，重扫成本可忽略），丢的行重启后自动补回。
2. **路由记账不能复用入库去重**。第一版改完后 @dsh **不再派单**了——因为服务自己写行时会顺手入库，
   扫描时把"已入库"误当成"已处理"。→ 现在两本账：入库去重 `dialogIds`、路由去重 `state.routedIds`；
   路由"先记账再做"，首次升级时把 Hub 里已有的看板行全标为已路由，避免重启把历史 `@dsh` 再派一遍
   （实测重启前后 inbox 任务数 15 → 15，`ROUTED SEEDED from hub: 181`）。
3. 顺带放宽解析：dsh 侧漏写过日期（`- @老板 21:31 dsh-老员工：在。`），现在自动补当天日期入库，
   以前这种行会被整条丢掉。

线上重启后 205 → 仍在的漏账已补、无重复派单。

## CT-009：找到"白屏"真因 —— 模板字符串把 `\n` 和 `\s` 吃掉了（2026-09-10 22:2x）

### 真因（不是布局，是语法）

```js
const line=String(last.body||"").split("
")[0];          // ← 字符串没闭合
```

`/^\s*@/` 变成 `/^s*@/`（@前缀识别失灵）。**已全部改成双反斜杠**（渲染出去才是真正的转义）。

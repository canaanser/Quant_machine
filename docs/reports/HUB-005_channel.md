**所以判据永远是"对方产生了回合"，不是投递返回 200**（这条写进 `AGENTS.md` 线间互通纪律）。

**规模化证据**：Hub 日志里 `DELIVERED+WOKEN` 累计 **21 次**（最近一次 2026-09-13 02:09 本地，发给本线）。

**判忙口径未被破坏**（卡 §四.3 验收）：`GET /api/deliver` 对 `lockPresent=true` 的线仍判
`action=inject`、reason「在岗且空闲 → 投递 + 唤醒」——**不因为"锁在"就判忙**（`codex-修复`、`codex-套件` 两条都实测）。

## 三、正式机制（本卡收口形态）

1. **推**：`codex queue` 门铃（不抢锁、穿透已开窗口）。入口在 Hub：`POST /api/mail {wake:true}` / 派单 / 公告扇出；沙箱外由 `crew_host` 的 `doorbell-queue` 小工兜底。

3. **兜底**：人肉插队（老板直接开那条线说一句）；**必达/准时的活交给 DSH 线**（它的门铃是平台级的）。
4. **可见化**（"可能没人处理"的状态必须看得见）：信箱未读 `pendingMail` / 「已投递未唤醒」标注 / **补投账本**。
